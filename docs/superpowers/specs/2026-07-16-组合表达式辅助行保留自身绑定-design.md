# 组合表达式辅助行保留自身绑定设计

## 问题

名字驱动模板铺量遇到多操作数表达式时，会记录各操作数对应的目标 Excel 行。例如运输定额表达式 `F27*10*0.05+F29*10*0.03` 以第 27 行为主行，同时使用第 29 行“拆除安装吊顶”的数量。

现有流程在处理第 29 行前先检查“已并入”标记，命中后直接生成一条空定额占位并跳过本行全部匹配。因此，即使模板已经保存了第 29 行自己的 `FY-1725`、`FY-2754`，仍不会显示。

## 目标行为

- 辅助行的数量继续参与主行的组合表达式计算。
- 辅助行有自己的模板匹配、对应框匹配或其他现有可靠匹配时，正常生成自己的全部定额。
- 辅助行生成自己的定额时，在组首状态中补充“同时参与第 N 行的表达式取数”，不再显示成被完全吞并。
- 只有辅助行经过全部现有匹配途径仍没有独立定额时，才保留空定额占位，并说明它仅参与第 N 行的表达式取数。
- 主行行为不变；第 27 行仍是运输表达式的承载行，不标记为辅助行。

## 方案比较

### 方案一：延后处理辅助取数标记（采用）

不在目标行循环开头直接跳过。先按现有顺序执行精确模板、模糊模板、对应框和无匹配兜底，再在预览结果生成完毕后统一附加辅助取数说明。有独立定额时保留定额；没有独立定额时把兜底行改为纯取数占位。

优点是覆盖所有既有匹配途径，且不会改变匹配优先级、表达式计算或组件组结构。

### 方案二：只对精确模板匹配放行

在循环开头发现精确模板组时忽略“已并入”标记，其余情况继续跳过。改动较小，但仍会错误屏蔽对应框或模糊模板匹配，不采用。

### 方案三：完全删除“已并入”提示

所有目标行都按普通行处理。实现最简单，但纯辅助取数行会变成“无对应定额”，用户无法知道其数量已经用于其他表达式，不采用。

## 实现设计

修改 `tools/RecoExpandPanel/TemplateFillNameMatch.cs`：

1. 保留多操作数替换及辅助目标行记录，但提示语改为“同时参与第 N 行的表达式取数”。
2. 删除目标行循环开头命中辅助标记后立即 `continue` 的分支。
3. 预览列表全部生成后，按 `TargetRow` 定位辅助行结果：
   - 组内存在非空定额编号时，只给组首追加辅助取数说明；保持勾选、候选、组件组和数量不变。
   - 组内没有定额编号时，保留单条未勾选占位，将其说明改为“参与第 N 行的表达式取数，无独立定额匹配”，并保持不可写入定额。
4. 不修改模板文件、Excel 绑定文件、对应框数据或目标 Excel。

## 南通西站预期结果

对于 `F27=2`、`F29=1.5`：

- 第 27 行继续生成地面拆除及运输定额；运输表达式继续代入 `F27` 和 `F29`。
- 第 29 行正常生成：
  - `FY-1725`，工程数量 `1.5*10`。
  - `FY-2754`，工程数量 `1.5`。
- 第 29 行组首显示其模板命中状态，并补充“同时参与第 27 行的表达式取数”。

## 验证

- 增加回归场景：辅助操作数行同时具有自己的精确模板组件组，确认组合表达式与辅助行自身定额同时存在。
- 增加回归场景：辅助操作数行没有任何独立匹配时，仍只显示清晰的取数占位，不产生错误定额。
- 运行现有模板铺量完整回归，确认同名候选、对应框、组件组回写、跨工作簿取数和数量换算不受影响。
- 与已完成的表头排序改动一起从干净提交构建 `RecoExpandPanel.dll`，验证发布 DLL 只包含已确认改动。

## 边界

- 不改变组合表达式的计算公式和主行选择规则。
- 不改变模板匹配优先级或自动勾选规则。
- 不要求重新生成现有模板；当前 `26站门禁` 模板中的 FY-1725、FY-2754 绑定可直接生效。
- 目标软件运行时不覆盖运行目录 DLL；最终部署等待软件关闭。
