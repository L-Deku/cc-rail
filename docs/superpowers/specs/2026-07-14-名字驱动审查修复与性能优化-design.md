# 名字驱动审查修复与性能优化设计

日期：2026-07-14
状态：用户已确认实施；代码与离线验证已完成，待主程序关闭后正式构建部署及界面回归
范围：`RecoExpandPanel` 名字驱动模板铺量、Excel 绑定回写、对应框写入；`RecoQuotaRecommend` 仅做兼容性验证

## 1. 目标

在不改变既有“列锚点”模式、普通推荐、Excel 即时填和软件原生定额输入行为的前提下，修正名字驱动链路中的章节错配、组件框拆散、右键重绑非原子和失败写入误学习问题，并减少批量绑定与大表预览的重复 Excel 读取、重复字符串计算和整文件写入。

## 2. 明确不变的行为

- Excel 数量为 `0` 的工程量行继续直接丢弃，不进入名字驱动预览。
- 模式一“列锚点”的匹配、预览、写入和撤销逻辑不改。
- 普通推荐入口仍按现有 `MappingStore`、索引和条目范围规则运行。
- 不把组件框、模板或学习数据写到当前工作区之外的新目录。
- 不自动恢复从旧 `learning.jsonl` 播种对应框；旧数据迁移保持显式、可审计，不在本轮运行时自动执行。
- 不新增后台 COM 访问。性能优化先通过单次文件快照、预计算和合批写入完成，避免引入线程亲和风险。

## 3. 章节内匹配

### 3.1 数据模型

`FillTemplateRow` 新增源 Excel 章节文本 `MatchChapter`。名字模式生成模板时，按“工作簿、工作表、数量列”建立一次源表章节快照：从工作表首个有效行向下扫描，遇到现有 `IsChapterAnchorRaw` 可识别的标题即更新当前章节；每条模板行按其 `SourceExpr` 首单元格所在行记录最近章节。

旧名字模板没有 `MatchChapter` 时，预览可根据仍保存的 `WorkbookPath`、`SourceSheet`、`SourceExpr` 临时补读；源文件不存在或无法识别时不得自动跨章节写入，只能产生黄色建议。不会在预览时静默改写旧模板文件。

### 3.2 匹配顺序

每个目标工程量行按以下顺序处理：

1. 源、目标章节归一化后完全相同：在该章节模板组内先精确名称匹配，再模糊匹配。
2. 章节名称高度相似且数字不冲突：允许作为同章节处理，阈值独立于工程量名称阈值并取保守值。
3. 章节不一致、任一方缺章节或章节无法识别：只计算跨章节黄色建议，`Selected=false`，不得自动写入。
4. 用户通过右键明确绑定软件选中的定额后，视为人工确认，可正常写入和回写。

模板组的“已使用”状态按章节兼容候选确定，不能由其他章节的同名行提前抢占。跨章节建议不提前消费模板组。

## 4. 组件框按整组回写和回读

### 4.1 写入模型

名字驱动反馈不再传递扁平的 `定额编号 -> 工程量名` 对，而是按 `TargetRow` 形成：

```text
工程量全名
└─ Targets[] = 定额一、定额二、……
```

对目标去重并按 `target_kind:target_code` 稳定排序，使用全部目标键生成稳定 `box_id`。同一组件框的每个目标记录使用同一个 `box_id` 和同一个工程量样本签名。权重、接受次数和最后使用时间在该样本的各目标记录上保持一致。

若文件中已存在目标集合完全相同的框，则在原框中增加或加权样本；目标集合不同的单定额框和旧组件框不合并、不删除。

### 4.2 回读模型

名字驱动对应框查询先按 `box_id` 还原框，再对框的样本名称打分。命中后返回该框的完整目标组，而不是只取全文件最高分的第一条目标。

模板铺量只能自动写入软件可处理的定额目标。包含材料或不支持伪代码的框不自动勾选，保留为黄色人工提示；`设备购置费` 的 `SF` 仍遵循现有项目规则，不扩大本轮范围。

## 5. 右键整组重绑的原子性

用户可在同一工程量组件框的任意成员行触发重绑，但实现必须按 `TargetRow` 找到完整组：

1. 读取软件当前选中定额行，在临时列表中完成编号、定额序号、条目、单位和数量换算验证。
2. 验证过程中不修改 `preview`。
3. 只要没有得到至少一条有效定额，原组件组保持完全不变。
4. 验证成功后一次性移除该 `TargetRow` 的所有旧成员，并在原组长位置插入新组。
5. 新组重新连续编号 `GroupOrder=0..N-1`；只有第一行显示工程量名，所有成员继承相同的全名、目标单位、原始数量和目标行。
6. 各成员保留自己真实的定额单位、条目序号和条目编号。

## 6. 只有真实写入成功才学习

直接数据库复制仍以返回的新定额序号作为成功依据。库内定额的原生粘贴路径在调用前记录撤销行数量，调用后只有确认新增撤销记录时才把该组加入 `writtenOk`；若不能确认整组成功，则整组不回写对应框和模板，避免把失败或部分失败当成已接受样本。

名字驱动反馈只接收最终确认成功的 `writtenOk` 子集。失败提示、跳过数和成功数必须与实际写入一致。

## 7. 性能优化

### 7.1 批量绑定

- 将“读取显示名/全名”和“写对应框”拆开；保存 Excel 绑定成功后才进入学习写入。
- 批量绑定为全部链接建立一次 `ExcelSyncReadContext`、隐藏列缓存和合并区域缓存。
- 所有成功绑定的学习记录在一次互斥锁中完成一次读取、批量 upsert、裁剪和一次写回。
- 单条绑定调用同一批量实现的单元素包装，避免两套逻辑。

### 7.2 名字驱动预览

- 每个“工作簿、工作表、数量列”只建立一次稀疏快照；章节、全名、显示名、单位和数量从同一上下文读取。
- 模板名称、章节名称和对应框样本预先计算归一化文本、数字集合及 bigram，打分循环不重复分配集合。
- 项目定额按编号建立字典，替代每个目标行的 `FirstOrDefault` 全表扫描。
- 对应框先按 `box_id` 建框和样本索引，再按目标工程量查询。
- 保持现有 UI 线程边界；本轮不把 COM、WinForms 控件或共享数据库连接放入后台线程。

## 8. 兼容策略

- 旧位置模板按默认 `MatchBy=position` 原样工作。
- 旧名字模板优先临时补读章节；补读失败时降级为黄色建议，不自动写入。
- 现有单定额框、组件框、样本权重和最多 30 个样本的裁剪规则保持兼容。
- `MappingStore.Load` 保持停止自动播种旧 `learning.jsonl`；另行提供迁移前应先有只读报告和用户明确确认，本轮不自动迁移用户数据。
- 不删除当前不可达的库内候选字段和分支，除非实现验证证明其确实无入口并再次确认产品范围。

## 9. 验证门禁

### 9.1 自动/反射测试

- 修复 `verify-samples.ps1` 对已改名检索接口的反射调用，使代表样例重新成为有效门禁。
- 章节：同名工程量位于两个章节且顺序互换，不得跨章自动认领；章节缺失只产生黄色建议。
- 组件框：`土方外运 -> LY-21 + LY-34 + LY-35` 回写后仍为一个 `box_id`，回读返回三条完整目标。
- 重绑：从组长或任一组员触发结果一致；无效软件选中行不改变原组。
- 写入反馈：原生插入失败或无法确认成功时不增加模板行、不增加对应框接受次数。
- 批量绑定：多条绑定只进行一次 mapping 文件写回；单条和批量生成的名字及权重一致。
- 数量为 `0` 的目标行继续不进入名字驱动预览。

### 9.2 实际软件回归

1. 模式一列锚点预览、写入、撤销、计算结果与修改前一致。
2. 名字模式生成、章节内匹配、跨章节黄色建议、右键整组重绑可用。
3. 一量多定额写入后定额数量、条目、单位、调整、计算结果和撤销正确。
4. 普通推荐中既有“土方外运”组件框仍返回完整组。
5. Excel/WPS 绑定、表达式换算和连续点选功能不回归。

### 9.3 性能验收

用相同工作簿分别记录修改前后的预览耗时，至少覆盖约 200、1000、5000 个 UsedRange 行；批量绑定覆盖 1、20、100 条。结果必须一致，且大表预览与批量绑定不得增加文件打开次数或 mapping 文件写回次数。

## 10. 实施顺序

1. 修章节隔离、组件框整组语义、右键原子替换和成功反馈。
2. 补齐并修复回归测试，先证明正确性。
3. 合并 Excel 快照、预计算匹配特征、项目定额字典和批量 mapping 写入。
4. 构建但在部署前确认目标软件关闭；先做离线验证，再做实际软件回归。
5. 只有全部门禁通过才保留部署产物；任何主体回归立即停止，不以性能收益换行为变化。
