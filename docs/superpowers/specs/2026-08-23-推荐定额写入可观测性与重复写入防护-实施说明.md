## 1. 批次 A：写入路径补结构化日志

### 1.1 问题

`038434d` 删除 L3 原生链时，把该链原有的全部诊断日志一并删除，未补等价物。

现状：`TemplateFillFeature.cs` 全文仅剩 5 处 `Log()`，且**全部位于与写入无关的失败分支**——`:505` 工作簿跳过、`:862` 章节名加载、`:1040` 隐藏列、`:1331` / `:1558` 学习回流失败。

**`ApplyFillToSelectedEntry`（`:1186`）主写入路径，成功与失败都不出声。**

后果已经真实发生：2026-08-22 的实施审查无法从 `RecoExpandPanel.log` 判断实机写入是否成功，只能绕道查学习库 `RecoLearning.BindingLog` 间接取证；而**学习回流只在整批完整成功时产生**——一旦写入失败或整组阻断，将不留任何痕迹，现场排障失去依据。

### 1.2 日志设施（不需要新建）

沿用 `FormPanel.Log(string)`（`FormPanel.cs:384`）：写入 DLL 同目录 `RecoExpandPanel.log`，UTF-8，带 `yyyy-MM-dd HH:mm:ss` 前缀，已有 `RotateLogIfNeeded` 轮转与 `LogLock` 串行化。

**不要**新增日志文件、日志级别、配置开关或异步队列。一次写入约产生 3–5 行，轮转机制足够。

### 1.3 统一前缀

全部使用 `Smart fill apply` 前缀，便于 `rg "Smart fill apply"` 一次捞全链路：

| 事件 | 行格式 |
|---|---|
| 进入 | `Smart fill apply begin: unit=<单元编号>#<单元序号> entry=<条目编号>#<条目序号> items=<n> groups=<n>` |
| 选路结果 | `Smart fill apply plan: L1=<n> L2=<n> sf=<n> entries=<条目编号:条数, ...>` |
| 成功 | `Smart fill apply ok: unit=<单元编号>#<单元序号> business=<n> marker=<n> undoRows=<n> firstId=<id> lastId=<id> elapsedMs=<n>` |
| 阻断（返回错误文案） | `Smart fill apply blocked: entry=<条目编号> <原样的返回文案>` |
| 事务失败 | `Smart fill apply failed: entry=<条目编号> <异常类型>: <异常消息> elapsedMs=<n>` |
| 界面侧拒绝 | `Smart fill apply rejected: <原因>` |
| 用户取消 | `Smart fill apply canceled: entry=<条目编号> items=<n>` |

## 2. 批次 B：重复写入防护

### 2.1 问题

实机已真实发生（`BindingLog` 取证）：

```
18:39:01  1 条  PY-415                          → 0309-01-03-06
18:39:35  15 条 BC00-4/6/8/10、PY-415/238/425/430/435、QY-214、QY-215*9、SY-153×2、ZLF×2 → 0309-01-03-06
18:54:04  16 条 完全相同的 15 条 + PY-387        → 0309-01-03-06
```

`PY-415` 可能已写入三次。当前实现**没有任何机制阻止或提示**：

- 写入成功后预览行、勾选状态、滚动位置全部保留——这是 `ec2c0bb` 的有意设计，服务于“预览一次、分批写多个条目”，**必须保留**；
- 但界面零变化，用户无从分辨哪些行已写过；
- `FillPreviewItem.WrittenQuotaSequence`（`TemplateFillFeature.cs:130`）**只写不读**，`TemplateFillPanel.cs` 中一次都没引用。

**不禁止重写**——同一定额写入不同条目是合法场景，同一条目下同编号不同工程量行也合法。本批只做“看得见 + 要重新勾 + 明确告警”。

### 2.2 两层防护，缺一不可

| 层 | 覆盖范围 | 局限 |
|---|---|---|
| **B1 界面标记 + 取消勾选** | 同一次预览内的重复写入 | **重新预览后标记清零**，管不住跨预览重写 |
| **B2 库内重复告警** | 跨预览、跨窗口、跨重启的真实重复 | 只告警不阻断 |

**B2 是必做项，不是可选增强。** 18:39 与 18:54 相隔 15 分钟，很可能是重新预览后重写的——那种情况下 B1 完全拦不住。只做 B1 等于没解决已发生的那个问题。

### 2.3 B1：写入成功后取消勾选并标注

#### 2.3.1 🔴 硬约束：不得把“已写入”写进 `FillPreviewItem.Status`

这是本批最容易踩的坑。`Status` 是**阻断语义字段**，任何非空值都会连锁触发：

| 位置 | 后果 |
|---|---|
| `TemplateFillPanel.cs:659` `RefreshApplyEnabled` | 组要求 `String.IsNullOrEmpty(item.Status)` 才算可写 ⟹ 写入按钮永久变灰 |
| `:1670` `IsNameQuotaHardStatus` → `:1682` `GetNameQuotaRowBackColor` | 行变 `MistyRose` 红底 |
| `:1645` `GetUnsafeNameQuotaCandidateReason` / `IsNameQuotaGroupSafeForWrite` | 整组被判为阻断，永远写不了第二次 |

同理也**不得复用 `AlignNote`**（会覆盖分诊提示）。必须新增独立字段。

这条与 `AGENTS.md:166` 已有的规则同源：「不得把该提示写入阻断性 `Status`」。

#### 2.3.2 新增字段

`TemplateFillFeature.cs`，`FillPreviewItem` 内 `WrittenQuotaSequence`（`:130`）下方：

#### 2.3.3 新增打标函数（可离线测试的接缝）

`TemplateFillFeature.cs`，紧邻 `ApplyFillToSelectedEntry` 之后：

```csharp
// 写入成功后给预览项打标：累加真实落点条目编号（SF 改道后与面板当前条目不同），并取消勾选，
// 迫使用户重新勾选才能再写一次。不触碰 Status/AlignNote——它们是阻断语义字段。
internal static void MarkSmartFillItemsWritten(IEnumerable<FillPreviewItem> items)
{
    foreach (FillPreviewItem item in items ?? Enumerable.Empty<FillPreviewItem>())
    {
        if (item == null || item.WrittenQuotaSequence <= 0) continue;
        string entryNo = (item.ChosenItemNo ?? "").Trim();
        if (entryNo.Length > 0)
        {
            List<string> parts = String.IsNullOrWhiteSpace(item.WrittenEntryNos)
                ? new List<string>()
                : item.WrittenEntryNos.Split('、').Select(part => part.Trim())
                    .Where(part => part.Length > 0).ToList();
            if (!parts.Contains(entryNo)) parts.Add(entryNo);
            item.WrittenEntryNos = String.Join("、", parts.ToArray());
        }
        item.Selected = false;
    }
}
```

要点：

- 以 `WrittenQuotaSequence > 0` 判定“确实落库”，保证标记与真实业务行一一对应，marker 行不参与；
- 取 `item.ChosenItemNo` 而非面板的 `entryNo`——**SF 改道行的真实落点是同级设备购置费条目**，展示面板条目号会说谎；
- 去重保序，同条目重复写不会刷屏。

private static string BuildSmartStatusCellText(FillPreviewItem item)

### 5.1 离线回归（隔离目录，带 NPOI 依赖，被测 DLL 即待部署版本）

`Test-SmartFillManualEntrySafety.ps1` 新增：

**源码标记**（沿用文件顶部 `$requiredPanel` / `$requiredFeature` 的写法）：

- feature 必须含：`MarkSmartFillItemsWritten`、`WrittenEntryNos`、`BuildSmartFillDuplicateWarning`、`LoadEntryQuotaCodes`、`Smart fill apply begin`、`Smart fill apply ok`、`Smart fill apply blocked`
- panel 必须含：`BuildSmartStatusCellText`、`RefreshWrittenSmartRows`、`Smart fill apply rejected`
- **反向断言**：feature 与 panel 源码均**不得**出现 `Status = "已写入`（防止后人把标记塞回阻断字段）

**反射行为用例**（`FillPreviewItem` 造项的写法照抄文件尾部 `New-Item`）：

1. `MarkSmartFillItemsWritten`：`WrittenQuotaSequence>0` 的项 → `Selected` 变 `false`、`WrittenEntryNos` 含 `ChosenItemNo`、`Status` 仍为空；
2. 同一项对同一条目写两次 → `WrittenEntryNos` 不重复；写不同条目 → 以 `、` 累加两个编号；
3. `WrittenQuotaSequence == 0` 的项 → `WrittenEntryNos` 保持空（但仍取消勾选）；
4. `BuildSmartStatusCellText`：`Status` 为空 + 有标记 → `已写入 <编号>`；`Status` 非空 + 有标记 → `<Status>；已写入 <编号>`；无标记 → 与旧行为逐字相同（含 `AlignNote` 回退）；
5. `BuildSmartFillDuplicateWarning`：桩注入已有编号集，有交集 → 文案含条目编号与重复的定额编号；无交集 → `""`；超过 5 个编号 → 含 `等 <总数> 条`；多条目 → 多行。

### 5.3 实机（用户操作，代理只读核对）

1. **日志覆盖**：正常写入一次 → 日志出现 `begin` / `plan` / `ok` 三行且计数自洽；
2. **阻断有痕**：故意制造一次整组阻断（如把某组数量改为 0）→ 日志出现 `blocked` 且原因可读；
3. **取消有痕**：确认框点取消 → 日志出现 `canceled`；
4. **标记与取消勾选**：写入成功后关掉提示框，已写组复选框为空、状态列显示 `已写入 <条目编号>`、滚动位置与预览行不变；未写组勾选保持；
5. **SF 改道标记正确**：混合组中 SF 行的标记显示的是同级设备购置费条目编号，不是面板当前条目；
6. **重复告警**：对同一条目重新勾选并再写一次 → 确认框顶部出现重复告警，点确定仍能写入（不阻断）；
7. **跨预览告警**：重新预览后再写同一批 → 告警仍然出现（证明 B2 独立于 B1 生效）；
8. **批次 C 跨单元验证**：按第 3 节走完。
