# 模板铺量定额材料稳定排序设计

## 问题

名字驱动模板铺量允许在预览中右键，把软件当前选中的多条定额或材料绑定到尚未预置关系的工程量。首次写入完成后，这组关系会同时回写到当前模板和对应框，供下次铺量直接命中。

当前 `26站门禁` 模板中的“圈梁 10m3”已经按正确先后保存：

1. `FY-842`，预拌混凝土现浇圈梁、过梁。
2. `109001003*1.02`，商品混凝土 C20（泵送）。

但两条新增记录的 `OrderInItem` 都是 `0`。预览重建时，现有排序只把 `SF`、`SH`、`ZLF`、`LF` 等辅助代码排到末尾，没有识别纯数字材料编号；当类别和 `OrderInItem` 都相同时，比较结果为相等，底层排序不保证保持模板原始行序，因此材料可能出现在定额前面。

## 目标行为

同一工程量绑定多条目标时，模板预览和后续写入统一使用以下顺序：

1. 普通定额。
2. 材料编号，包括纯数字编号以及带 `*系数` 的纯数字编号。
3. `SF`、`SH`、`SQ`、`ZLF`、`LF`、`YF`、`TLF`、`GF`、`JF`、`XGT1` 等辅助代码。

同一类别内继续尊重已有 `OrderInItem`；如果 `OrderInItem` 也相同，则以模板原始行位置作稳定兜底，不能再随机交换。

## 方案比较

### 方案一：统一目标类别排序并增加稳定兜底（采用）

在模板组和对应框组共用的排序入口中识别普通定额、数字材料和辅助代码。模板组额外使用原始行下标作为最终比较项。

优点是现有模板无需重新生成或重新绑定，当前圈梁数据可以直接恢复正确顺序；模板命中和对应框命中也遵守同一类别规则。

### 方案二：仅在回写时重新分配 `OrderInItem`

只修复今后新增的关系，已经保存成相同序号的模板仍可能错序，对应框预览也不会同步修复，不采用。

### 方案三：只在表格显示前调整行序

界面看起来正确，但写入列表和对应框候选仍可能保持错误顺序，造成显示与实际写入不一致，不采用。

## 实现设计

修改 `tools/RecoExpandPanel/TemplateFillNameMatch.cs`：

1. 将现有只识别辅助代码的排序函数调整为统一目标类别排序函数。
2. 判断材料前先去掉编号末尾的 `*系数`；去除后为五位及以上纯数字时按材料处理。
3. `OrderedTemplateGroupIndexes` 按“目标类别、`OrderInItem`、模板原始行下标”依次比较。
4. `BuildMappingBoxIndex` 继续保持确定性排序，但改为先按目标类别，再按编号排序。
5. 不改模板 JSON、对应框 JSONL、Excel 绑定数据及自动匹配评分。

## 数据流

右键整组绑定时仍按软件表格中的实际行序生成预览组；写入成功后的回写逻辑保持不变。再次铺量时，模板或对应框加载出完整目标组，再由统一目标类别排序生成 `GroupOrder`。写入阶段沿用该预览顺序，因此界面和实际写入保持一致。

## 验证

- 增加圈梁回归组：`FY-842` 与 `109001003*1.02` 的 `OrderInItem` 同为 `0`，确认预览仍为定额在前、材料在后。
- 增加辅助代码回归项，确认顺序为普通定额、数字材料、辅助代码。
- 增加同类别同序号回归，确认以模板原始行位置稳定排序。
- 运行 `Test-TemplateFillNameMatch.ps1` 全部既有场景，确认模板匹配、对应框、同名候选、组合表达式和数量换算不受影响。

## 边界

- 不重新生成或重写现有模板。
- 不改变右键绑定保存的目标集合。
- 不改变工程量名称匹配、章节判断、自动匹配得分或勾选规则。
- 不修改绑定 Excel 和模板铺量窗口已经禁用的表头排序行为。
- 构建和部署仍遵守软件关闭、干净源码构建、发布包同步及工作区外部署需另行授权的现有规则。
