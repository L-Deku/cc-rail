反复失败不是实现能力问题，是**验收口径自相矛盾**：AGENTS.md 要求「滚动必须整列失效重绘」，

三条同时成立不可满足，codex 只能在两个症状之间来回摆。
本批要做的是**把口径合并成一对不可拆分的约束**，代码只改两处。

### 1.2 三处口径的原文

**A. AGENTS.md「UI 行为规则」（已提交，现行有效）**

> 名字驱动预览把工程量名跨组件成员行合并绘制时，应由当前正在绘制的成员单元格作锚点，
> 按组内各行高度反推出**同一个稳定整组矩形**，再分别裁剪绘制；……
> **选择变化和滚动事件都必须使合并工程量名整列或完整组失效重绘**，
> 并用「滚动多行组件无空白无重叠、点击后续成员行首行文字仍完整」做现场验收。

**B. `tools/RecoExpandPanel/TemplateFillPanel.cs:1966-1972`（现行代码）**

```csharp
Rectangle dataBounds = ownerGrid.ClientRectangle;
if (ownerGrid.ColumnHeadersVisible) { ... }
result.Intersect(dataBounds);   // ← 把整组矩形裁到可见数据区
```

**C. `tools/RecoExpandPanel/tests/Test-TemplateFillNameMatch.ps1:914-918`（工作树未提交）**

```powershell
$scrollHandlerSource = [regex]::Match($panelSource, 'grid\.Scroll\s*\+=\s*delegate[\s\S]*?\n\s*};').Value
if ($scrollHandlerSource -match 'InvalidateColumn|\.Update\(\)|\.Refresh\(\)') {
    throw '滚动事件不得强制失效或同步刷新目标工程量名称列'

```

### 1.3 为什么三条不可同时满足

- B 的 `Intersect(dataBounds)` 让**同一成员行的绘制结果依赖当前滚动位置**：
  组跨越视口上边界时，裁剪后的矩形变矮，文字的垂直居中点随之上移。
- `DataGridView` 垂直滚动走的是「位块搬移旧像素 + 只重绘新暴露行」。
  其他列的内容与滚动位置无关，搬移后仍然正确；
  唯独 `tname` 列留在屏幕上的成员行保留着**按旧视口算出的文字位置** → 空白 / 半截字 / 重影。
- 所以 B 一旦存在，C 就必然出错；C 一旦成立，A 就被违反。
- 反过来，A 说要「稳定整组矩形」，B 的视口裁剪本身就不稳定 —— **A 内部也不自洽**。

### 1.4 `grid.Update()` 是被测试逼出来的，不是现场需求

被 `f79551f` 满足、又被工作树删掉的旧断言：

```powershell
$scrollGrid.FirstDisplayedScrollingRowIndex = 10
if ($script:mergedNamePaintCount -eq 0) { throw '滚动事件返回时目标工程量名称列尚未同步重绘' }
```

程序化设置 `FirstDisplayedScrollingRowIndex` 后不跑消息泵，**任何正常的 WinForms 绘制都不会发生**。
要让这条断言通过，只能在 `Scroll` 事件里调 `grid.Update()` 强制同步绘制。
现场真实症状是「空白」（`Invalidate` 就能修）；「同一帧内完成绘制」只有不跑消息泵的测试能观测到。
`Update()` 修的是测试，代价是每条滚动消息里嵌套一次同步绘制。

### 1.5 当前这版测试没有判别力

`grid.Scroll` 处理器整个删掉后，`[regex]::Match(...)` 匹配为空串，
`'' -match 'InvalidateColumn'` 为假 → **断言空跑通过**。
所以现在这版测试对「有没有滚动重绘」完全无法判别，
`RecoQuotaRecommend/bin/RecoExpandPanel.dll`（09-01 08:22 构建）就是在这个状态下产出的。

## 2. 根因定性

> 自绘单元格的输出必须只是（行、列、单元格状态）的函数。
> 一旦它还依赖滚动偏移，`DataGridView` 的位块搬移优化就失效，
> 必须由调用方在每次滚动后让受影响区域整体失效 —— **这两件事是绑定的一对。**

`f79551f` 和工作树改动各拿走了一半，所以两边都错。

## 3. 两个自洽方案

### 方案 A（本批选定）— 保留视口裁剪 + 滚动只做异步整列失效

- 矩形继续裁到可见数据区 → 组跨越视口边界时**名称仍完整可读**（贴边显示）。
- `Scroll` 事件里**只调 `InvalidateColumn`，绝不调 `Update()` / `Refresh()`**：
  失效区域会与滚动自身产生的重绘合并成一次 `WM_PAINT`，不阻塞连续滚动。
- 满足 AGENTS.md 的现场验收标准「滚动多行组件无空白无重叠」。

### 方案 B（备选，本批不做）— 去掉视口裁剪，滚动零重绘

- 删掉 `result.Intersect(dataBounds)`，矩形随滚动整体平移 → 位块搬移永远正确 → `Scroll` 处理器可彻底删掉。
- 代价：组跨越视口上边界时文字跟着组滚出去，可见成员行会显示**半截字或空白**，
  违反 AGENTS.md 现行验收标准。只有在用户明确接受「像 Excel 合并单元格那样滚出去」时才可切换。

**不得各取一半。** 只要保留 `Intersect(dataBounds)`，`Scroll` 里的 `InvalidateColumn` 就是必需项。

## 4. 代码改动（共两处，都在 `tools/RecoExpandPanel/TemplateFillPanel.cs`）

### 4.1 恢复 `grid.Scroll`，只失效、不同步刷新

位置：`grid.SelectionChanged += delegate` 之前（当前工作树 371 行上方）。

```csharp
grid.Scroll += delegate(object sender, ScrollEventArgs se)
{
    // 合并工程量名的矩形 = 整组矩形 ∩ 可见数据区，取值依赖当前滚动位置；
    // 而 DataGridView 垂直滚动只搬移旧像素 + 重绘新暴露行，
    // 留在屏幕上的成员行会保留按旧视口算出的文字位置（空白 / 半截字 / 重影）。
    // 因此这里必须让整列失效。只做异步 Invalidate，让它与滚动自身的重绘合并成一次 WM_PAINT；
    // 不得调用 Update()/Refresh()：那会在每条滚动消息里嵌套一次同步绘制。
    if (se.ScrollOrientation != ScrollOrientation.VerticalScroll) return;
    if (grid.Columns.Contains("tname"))
        grid.InvalidateColumn(grid.Columns["tname"].Index);
};
```

要点：

- 参数必须写成 `delegate(object sender, ScrollEventArgs se)`，`DataGridView.Scroll` 是 `ScrollEventHandler`。
- 横向滚动时矩形随单元格整体平移，搬移结果正确，直接早退，不做多余失效。
- 只失效 `tname` 一列，不要 `grid.Invalidate()` 整表。

### 4.2 `GetVisibleMergedTargetNameBounds` 补足契约注释（`:1948-1974`）

逻辑**不改**，只在 `result.Intersect(dataBounds);` 上方补注释，写明它与 4.1 是绑定的一对：

```csharp
// 裁到可见数据区，保证组跨越视口边界时名称仍完整可读。
// 注意：这使本函数的结果依赖当前滚动位置，位块搬移不再成立，
// 因此 grid.Scroll 必须配套让 "tname" 整列失效（见构造函数中的 Scroll 处理器）。
// 删除这一行或删除那个处理器都会立刻重现滚动空白，两者不得单独取舍。
result.Intersect(dataBounds);
```

## 8. 现场验收（缺一不可）

在推荐定额窗口，用至少含一个 3 行以上组件组、总行数超过一屏的预览：

1. 鼠标滚轮**连续快速上下滚**：合并工程量名不出现空白、半截字、重影，也不出现明显卡顿或撕裂。

5. 横向滚动（若有横向滚动条）：名称跟随列平移，无重影。

## 12. 实测后改判（2026-09-01 晚）：最终采用方案 B，§3–§6 的方案 A 作废

方案 A（视口裁剪 + 滚动异步 `InvalidateColumn`）按 §4–§7 实施、部署（`988fc9b`）后，
用户现场反馈：**滚动时 `tname` 列有延迟，与其他列不同步**。

原因是 §3 低估了这一点：位块搬移是即时上屏的，而 `WM_PAINT` 只在消息队列空闲时才派发；
滚轮 / 拖动滚动条期间消息不断，`tname` 列就始终显示搬移过来的旧内容，肉眼可见地慢一拍。
把它改成同步 `Update()` 就回到 `f79551f` 的卡顿。两种补救都被否决，说明**只要绘制结果依赖滚动位置，就没有不晚一拍又不卡的解**。

最终口径：

- `GetVisibleMergedTargetNameBounds` 改名 `GetMergedTargetNameBounds`，删掉 `Intersect(dataBounds)`，矩形只由锚点单元格和组内行高反推，与滚动位置无关。
- 删除 `grid.Scroll` 处理器，构造函数里留注释说明为何故意没有。
- 组首滚出表头后名称随组滚出，与 Excel 合并单元格一致，属预期行为。
- 回归改为：滚动事件返回前无同步绘制；滚动只重绘新暴露行（不得整列重绘）；同一组相对锚点单元格的偏移与高度在两个滚动位置一致；组首滚出表头后矩形 `Top` 小于表头高度（未被裁剪）。夹具在组后补 20 行，使“组员成为首行”真实可达。
- AGENTS.md 对应规则同步改写。

§8 现场验收改为：滚轮连续快滚、拖动滚动条，`tname` 列与相邻列**逐帧同步**移动，无延迟、无重影、无卡顿；组首滚出表头后名称随组滚出；点击组内后续成员行首行文字仍完整。
