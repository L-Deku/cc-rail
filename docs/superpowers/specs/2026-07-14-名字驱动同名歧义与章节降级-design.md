# 模板铺量·名字驱动同名歧义与章节降级设计

日期：2026-07-14
状态：用户已确认设计，待审阅后编写实施计划
承接：

## 1. 背景与问题

当前名字驱动预览把来源章节作为自动认领的硬条件：来源章节缺失、目标章节缺失或两者不兼容时，即使工程量名称完全相同，也只能生成黄色“跨章节建议”。

现场模板 `29站门禁` 共 53 条模板记录，所有记录的 `MatchChapter` 均为空。因此当前规则会把大量本应由名称唯一确定的结果统一标黄。模板记录的 `ItemNo` 虽可分为 `07`、`08` 两类，但以条目编号反推章节仍会让名字驱动依赖项目编号结构，不能解决所有旧模板或扁平 Excel 的问题。

名字驱动的核心证据应当是工程量名称。章节只在少量同名或近似名场景中提供辅助判断，不应因为章节缺失而否决唯一、明确的名称匹配。

## 2. 目标

- 章节不再作为名字驱动自动匹配的硬性过滤条件。
- 名称唯一且匹配明确时直接认领，不因章节缺失或不同而标黄。
- 对真正的一名多处歧义标红并禁止默认勾选，避免跨位置错误认领。
- 区分正常的“一项工程量对应多条定额”组件与真正的同名冲突。
- 保持数量为 0 直接丢弃、组件框、手工重绑、写入、撤销和成功后学习等主体行为不变。
- 通过预分组和名称索引减少预览阶段的重复扫描，不新增后台 COM 或线程复杂度。

## 3. 核心定义

### 3.1 归一化工程量名称

沿用现有 `NormalizeMatchText` 规则。完全匹配均指归一化后的名称完全相同，而不是仅比较界面截断文本。

### 3.2 来源锚点

模板记录的来源锚点定义为：

```text
工作簿 + 工作表 + SourceExpr 中第一个有效单元格地址
```

例如 `D2`、`D2/100` 的来源锚点均为 `D2`；`D27*10*0.05+D29*10*0.03` 的来源锚点为 `D27`。

### 3.3 正常组件组

归一化名称相同且来源锚点相同的多条模板记录，视为一个正常组件组。这些记录可以拥有不同定额编号、条目编号和数量换算表达式，预览时仍应作为“一项工程量对应多条定额”整体展开。

例如同一 `D2` 产生 `DY-519` 与 `ZLF*1.01`，属于正常组件，不标红。

### 3.4 真正的同名歧义

满足任一条件即属于同名歧义：

1. 目标 Excel 的有效工程量行中，归一化名称相同但位于两个或更多不同目标行；
2. 模板中归一化名称相同，但来自两个或更多不同来源锚点。

同名歧义意味着系统无法只凭名称确定一一对应关系。涉及的目标行标红、默认不勾选，不消费任何模板组件组，也不自动学习。

## 4. 匹配规则

### 4.1 预处理

读取目标数量列后，数量为 0 的行继续直接丢弃。对剩余目标行和模板记录分别建立：

- `归一化名称 -> 目标行列表`；
- `归一化名称 -> 来源锚点组件组列表`；
- 名称特征缓存，包括数字集合和 bigram。

章节文本可以继续保留在模板和目标快照中，但不参与候选过滤。

### 4.2 完全名称匹配

对每个目标工程量行按以下规则处理：

1. 目标名称在目标表中唯一，且模板中只对应一个来源锚点组件组：直接命中并默认勾选；
2. 目标名称在目标表中重复：所有同名目标行标红；
3. 模板中同一名称对应多个来源锚点组件组：对应目标行标红；
4. 同一来源锚点组件组内有多条定额：完整展开，只有第一行显示工程量名称，沿用组件框 UI 规则。

章节缺失、章节不同均不会改变上述结果。

### 4.3 模糊名称匹配

没有完全名称命中的目标行继续使用现有名称相似度阈值：

- 只有一个最高分候选组件组且达到阈值时，可自动命中；
- 多个候选并列最高分或无法形成唯一最佳候选时，标黄并提示“名称候选不唯一，需人工确认”；
- 当候选分数相同且双方均有章节信息时，章节兼容性只可作为二级排序证据；章节不得淘汰候选，也不得把唯一候选降级为黄色；
- 未达到阈值时沿用现有对应框推荐、空定额或手工挂定入口。

### 4.4 模板组消费

只有成功自动认领或用户明确确认的组件组才进入已使用集合。红色同名歧义和黄色不唯一建议均不得提前消费模板组，避免影响后续目标行。

## 5. 预览颜色与状态

- 默认底色：名称唯一且匹配明确，可正常写入；
- 黄色：相似名称存在多个不唯一候选、低置信推荐或现有待人工确认场景；
- 红色：同名多来源、目标多行同名、无条目锚点、数量读取失败等不能安全自动处理的场景。

红色状态必须给出可区分的原因：

- `目标表存在重复工程量名称，需人工确认`；
- `模板存在同名多来源，需人工确认`；
- `无条目锚点` 等既有错误文案保持不变。

用户手工匹配或明确选定后，沿用现有规则取消标红并允许勾选。

## 6. 章节数据的兼容处理

- `MatchChapter` 字段继续保留，兼容已有模板文件和历史反馈数据。
- 新模板生成时可继续在现有 Excel 快照中记录能识别到的章节，但章节为空不影响名字匹配。
- 预览热路径不再为了满足硬门槛而强制重新打开来源工作簿补读章节；旧模板来源文件不存在时也可按名称工作。
- 章节只在模糊候选完全同分时作为可选二级排序证据，不改变完全名称唯一匹配结果。
- 不使用 `ItemNo` 前两位作为强制章节映射，避免把项目编号结构变成新的隐含依赖。

## 7. 性能设计

### 7.1 精确匹配索引

模板组件组和目标工程量行一次性按归一化名称建字典。完全匹配由逐行遍历全部模板改为字典查询，使大量唯一同名行直接完成匹配。

### 7.2 模糊匹配范围

只有未被精确匹配、也未被判定同名歧义的目标行进入模糊打分。名称特征预计算一次，避免重复构造数字集合与 bigram。

### 7.3 Excel 读取边界

继续复用一次目标表快照，不新增 COM 读取。取消章节硬门槛后，不为旧模板章节补读额外打开源工作簿，减少预览等待和源文件依赖。

## 8. 写入与学习边界

- 正常组件组继续按整组写入，数量换算、定额调整、条目落位和撤销行为不变。
- 红色同名歧义默认不勾选，不进入 `writtenOk`，不得写回模板或 `mapping-boxes.jsonl`。
- 用户通过现有手工匹配入口明确选择后，才按真实成功写入结果学习。
- 同名目标行即使数量相同也不能据此自动推断对应关系；数量不是身份键。
- 不改变“只有真实写入成功才学习”的既有门禁。

## 9. 验证门禁

### 9.1 自动与反射测试

1. 模板和目标章节均为空，唯一完全同名时正常命中且默认勾选。
2. 模板和目标章节不同，唯一完全同名时仍正常命中。
3. 同名模板记录来自同一来源锚点，但包含多条定额时，作为一个组件组展开且不标红。
4. 同名模板记录来自两个不同来源锚点时，目标行标红、默认不勾选、模板组不被消费。
5. 目标表两个有效行名称相同时，两行均标红且不自动认领。
6. 模糊匹配只有一个最高分候选时沿用阈值命中；最高分并列时标黄。
7. 章节信息只参与模糊同分候选的二级排序，不淘汰唯一候选。
8. 数量为 0 的工程量继续不进入预览。
9. “无条目锚点”仍标红，状态文案与同名歧义可区分。
10. 红色或黄色未确认行不触发模板、对应框学习。

### 9.2 现场场景

使用 `29站门禁` 模板回归：

- 不再因为 53 条 `MatchChapter` 全为空而将大多数结果统一标黄；
- `D2`、`D2/100` 等同锚点多定额仍组成完整组件；
- 目标表真实重复名称或模板真实多来源名称明确标红；
- 写入数量、定额顺序、组件框、撤销与计算结果保持不变。

## 10. 实施与部署边界

1. 先修改匹配分组、颜色状态和测试，不改其他插件功能。
2. 验证只使用工作区内的源码、测试和构建输出。
3. 用户本轮明确要求暂不部署，因此不得把新 DLL 写入任何软件运行目录。
4. 完成代码和离线验证后，单独报告变更、测试结果及未部署状态；只有用户再次明确同意后才部署并做实际软件界面回归。
