## 2. 阻断项

### B1. 辅助码「同码已存在」门禁会锁死纯辅助推荐

**位置**：`tools/RecoExpandPanel/SmartFillFeature.cs:956-961`，`IsSmartMapEntryUsableInCurrentProject`

```csharp
bool sameCodeExists = currentQuotaByCode != null && currentQuotaByCode.Values.Any(quota =>
    quota != null && String.Equals(GetLearningBaseTargetCode(quota.Code),
        GetLearningBaseTargetCode(target.Code), StringComparison.OrdinalIgnoreCase));
ProjectQuota exactAuxiliary;
if (sameCodeExists && !TryGetCurrentSmartQuota(currentQuotaByCode, target, out exactAuxiliary)) return false;
```

**缺陷**

`SH`/`SF`/`ZLF`/`TLF` 是**共享伪代码**，同一编号承载多种不同材料。学习库只读实测：

| 目标编号 | 不同 `target_name` 数 |
|---|---|
| `SH` | **58** |
| `SF` | **19** |

一个项目同时存在多条不同 `SH` 是**常态**（征地拆迁场景尤其如此：水田、坟墓、民房、青苗补偿、消纳费、电缆沟…）。

`GetLearningBaseTargetCode`（`ExcelLinkFeature.cs:2774`）只剥 `*` 与 `/` 后缀，`SH` 归一后仍为 `SH`，因此 `sameCodeExists` 对任意 `SH` 目标必然为真。

**复现路径**

```
前置：当前项目 定额输入 已有一行  SH | 弃土消纳费 | m3
操作：预览并尝试推荐        SH | 水田       | 亩
实际：sameCodeExists = true
     TryGetCurrentSmartQuota(quota|SH|水田|亩) 未命中
     → return false → 整个组件在推荐阶段即被过滤，用户看不到
```

**影响**

只要项目使用过任意一条 `SH`，其余 57 种 `SH` 材料**永久无法被推荐**；`SF`/`ZLF`/`TLF` 同理，且**越用越少**。

这与用户 2026-08-11 拍板的「纯辅助开放」（设计决定 8）以及 L2 层的存在理由**直接冲突**——L2 的全部意义就是处理「当前项目尚无此条」。

**建议修法**

删除整个 `sameCodeExists` 判定分支。其上已有的「名称或单位为空则拒绝」才是必要的身份完整性安全网；身份精确命中走 L1，未命中走 L2，无需拒绝。

代码注释中「若项目已有同码记录，必须按完整名称+单位身份一致」的前提不成立——共享伪代码下同码多义是设计使然（AGENTS.md:84）。

**复审通过标准**（对应 v2.3 验收第 24 / 25 / 50 条）

项目内已存在 `SH 弃土消纳费` 时，`SH 水田` 仍能正常出现在预览中，并按 L2 构造完整行写入；两者名称、单位、单价互不串用。
