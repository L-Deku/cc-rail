# 推荐定额 L3 改为 SQL 构造 · 实施说明

> 文档性质：**实施说明**，供 codex 执行。前置结论见
> `2026-08-21-推荐定额写入路径统一方案.md`。
>
> **前置验证已通过**（用户 2026-08-21 实机确认）：写入行经「重算」后，
> **单价与合价与手工输入完全一致**。方案的唯一真实风险点已清除。

## 1. 一句话

把 L3「正式编号原生输入」删掉，让正式定额和辅助码走**同一条**「克隆结构模板 + SQL 插入」路径。

---

## 2. 关键前提：元数据早已在手，不需要新数据源

实施前请先确认这一点，它决定了改动量：

`SmartFillFeature.cs:1642-1644` 构造预览项时已经填好：

```csharp
SourceName = currentQuota == null || String.IsNullOrWhiteSpace(currentQuota.Name)
             ? target.Name : currentQuota.Name,   // 当前版本定额名
Unit       = currentQuotaUnit,                    // 当前版本单位
LearnedUnitPrice = ResolveSmartPreviewUnitPrice(target, currentQuota),
```

`currentQuota` 来自 `LoadCurrentSmartQuotaMetadata`，正式定额的名称/单位由 `quota-index*.jsonl`（定额库索引）补齐（`SmartFillFeature.cs:937-946`）。

且 `IsSmartMapEntryUsableInCurrentProject`（`:942-977`）**强制要求**正式定额必须在 `currentQuotaByCode` 中解析成功，否则整个组件不进推荐。

⟹ **凡是能走到写入路径的正式定额，`item.SourceName` 与 `item.Unit` 一定非空。**

**因此不需要**：新连数据库、DPAPI 凭据、跨库查询、读 `定额库` 表。

单价方面：`ResolveSmartPreviewUnitPrice`（`:952-958`）对非辅助码直接 `return 0m`，正式定额的 `LearnedUnitPrice` 本就是 0，正好交给重算补齐——与已验证的行为一致。

## 3. 核心改动：选层逻辑

**位置**：`tools/RecoExpandPanel/TemplateFillFeature.cs:2118-2143`

**现状**：

```csharp
PreparedSmartFillItem plan = new PreparedSmartFillItem { Item = item, SourceRow = source };
if (source != null)
{
    plan.Layer = SmartFillWriteLayer.L1;
    ... // 从源行取单价
}
else if (IsContextSensitiveLearningCode(item.QuotaCode))
{
    if (String.IsNullOrWhiteSpace(item.SourceName) || String.IsNullOrWhiteSpace(item.Unit))
        return "辅助码缺少完整名称或单位，整组未写入：" + (item.QuotaCode ?? "");
    ... // 取结构模板 + BuildSmartFillL2Row
    plan.Layer = SmartFillWriteLayer.L2;
}
else
{
    plan.Layer = SmartFillWriteLayer.L3;      // ← 删掉这一支
}
```

**改后**：去掉 `IsContextSensitiveLearningCode` 条件，让两类目标共用构造分支；`else` 分支整个删除。

```csharp
PreparedSmartFillItem plan = new PreparedSmartFillItem { Item = item, SourceRow = source };
if (source != null)
{
    plan.Layer = SmartFillWriteLayer.L1;
    ... // 保持不变
}
else
{
    // 辅助码用学习到的名称/单位/单价；正式定额用当前版本定额库的名称/单位，
    // 单价保持 0，由宿主「重算」补齐（已实机验证与手工输入一致）。
    if (String.IsNullOrWhiteSpace(item.SourceName) || String.IsNullOrWhiteSpace(item.Unit))
        return "目标缺少完整名称或单位，整组未写入：" + (item.QuotaCode ?? "");
    Dictionary<string, object> structuralRow;
    if (!structuralRows.TryGetValue(item.ChosenItemSeq, out structuralRow))
    {
        structuralRow = LoadSmartFillStructuralRow(conn, targetUnitSeq, item.ChosenItemSeq);
        structuralRows[item.ChosenItemSeq] = structuralRow;
    }
    if (structuralRow == null) return "当前项目没有可用于构造完整业务行的结构，整组未写入。";
    plan.Layer = SmartFillWriteLayer.L2;
    plan.SourceRow = BuildSmartFillL2Row(structuralRow, item);
}
```

**`BuildSmartFillL2Row`（`:1195`）一行都不用改** —— 它设的 7 类字段（定额编号 / 工程或费用项目名称 / 单位 / 定额调整 / 工程数量输入 / 工程数量 / 各费用列置 0 / 单价）对正式定额同样正确。

**`LoadSmartFillStructuralRow`（`:1154`）不用改** —— 三级兜底（目标条目 → 同单元 → 全表）已经足够。

> 命名建议：`SmartFillWriteLayer` 只剩 L1/L2 后，可把 L2 重命名为更中性的名字（如 `Constructed`），或保留 L2 但更新注释。不影响行为，由实施者决定。

### 6.2 `AGENTS.md` 两条已被实机推翻的结论

**其一**（2026-08-20 加入）：

> `dataGridViewDE` …表格、定额编号列和单元格均为只读，`BeginEdit(true)` 返回 false 且不会产生 `EditingControl`

该结论仅在**宿主窗体非当前活动窗口**时成立（跨窗口 `grid.Focus()` 不取得键盘焦点）。

**其二**：

> 推荐定额 L3 正式编号不得使用宿主右键菜单/批量粘贴作为写入路径；已验证该路径可返回却不生成定额行
