# 模板铺量重复名称定额候选设计

日期：2026-07-14
范围：`tools/RecoExpandPanel/` 的模板铺量“二·名字驱动”预览和定额候选交互

## 1. 目标

目标 Excel 中存在重复工程量名称时，继续用浅红色提示需要人工确认，但不再把对应定额留空：

- 模板中该工程量名称只有一个绑定组时，每个重复目标行都预填同一个绑定组。
- 模板中该工程量名称有多个绑定组时，在“定额编号”列提供下拉候选，由用户为每个目标工程量行分别选择。
- 同一源工程量单元格绑定的多条定额仍是一个必须整体写入的组件组，不能拆成互斥的单条定额候选。

本轮只修改名字驱动的精确同名处理和预览表交互，不改变列锚点模式、模糊匹配、对应框建议、右键整组重绑、写入事务和反馈学习规则。

## 2. 术语与边界

### 2.1 绑定组

继续沿用现有 `TemplateNameGroup` 语义：归一化工程量名称和源 Excel 锚点相同的模板行属于一个绑定组。

- 一个绑定组只有一条模板行时，是单定额绑定。
- 一个绑定组包含多条模板行时，是组件组。例如同一源单元格同时绑定 `DY-519 + ZLF*1.01`，两条必须共同选择、共同写入。
- 相同工程量名称来自不同源 Excel 锚点时，形成多个绑定组，才属于可下拉选择的不同方案。

### 2.2 候选显示

下拉项按绑定组显示，不按组内单条定额拆分：

- 单定额组：`DY-959  砖、混凝土结构明配镀锌钢管 公称口径≤20`
- 组件组：`DY-519 + ZLF*1.01（组件2条）`
- 若两个候选的显示文字仍相同，在末尾增加源表达式，例如 `（来源 D23/100）`，保证用户能区分。

## 3. 精确同名处理规则

### 3.1 目标名称重复、模板只有一个绑定组

同一个绑定组允许被多个精确同名目标行复用，不再受 `usedGroups` 的一次性消费限制。每个目标行都展开该绑定组的完整定额成员，并按各自数量重新计算数量文本和单位换算。

初始状态：

- 定额编号、名称、单位和数量均正常显示。
- 整个目标工程量组使用浅红底。
- 默认不勾选，状态显示“目标表存在重复工程量名称，已带出唯一绑定，需确认”。
- 用户勾选该目标工程量组后，视为确认该唯一绑定：整组同步勾选、取消浅红底，状态改为“人工确认重复名称”。

`29站门禁` 模板中的“钢管 SC20 m”只有 `DY-959` 一个绑定组，因此目标表里所有同名工程量行都会预填 `DY-959`。

### 3.2 模板存在多个同名绑定组

无论目标表中该名称出现一次还是多次，每个目标工程量行都显示一个确定的初始候选，避免定额列空白，同时保持浅红底和默认不勾选。

- “定额编号”列的组首行改为下拉单元格。
- 初始显示按模板稳定顺序排列的第一个候选，但该初始显示不代表已确认。
- 用户选择下拉项后，按所选绑定组原子替换该目标行当前展开的整个定额组。
- 替换后整组同步勾选，取消浅红底，状态改为“人工选择同名绑定”。
- 每个重复目标行独立选择；选择其中一行不自动改变其他同名目标行。

### 3.3 组件完整性

候选组的切换、勾选和写入都以 `TargetRow` 对应的完整绑定组为单位：

- 组件组首行承载工程量名称和下拉框。
- 后续成员行继续把工程量名称留空。
- 选择组件候选时展开全部成员，不允许只选 `DY-519` 而丢掉同组的 `ZLF*1.01`。
- 选择另一候选时，必须先完整生成替换组；生成失败则保留原组并提示，不做部分替换。

## 4. 数据与界面设计

为名字驱动预览项增加仅供本次预览使用的候选组信息。候选信息来自当前模板内的 `TemplateNameGroup`，不写入模板 JSON、对应框或数据库。

预览构建流程：

1. 读取目标工程量并统计归一化名称出现次数。
2. 按归一化名称取得全部模板绑定组。
3. 精确候选只有一组时，为每个目标行分别克隆完整绑定组。
4. 精确候选多于一组时，为每个目标行保存全部候选组，并用第一组生成未确认预览。
5. 非精确名称继续执行现有唯一最佳模糊匹配；模糊最高分并列仍保持黄色人工提示，不引入本轮下拉。

界面复用自动匹配窗口现有 `DataGridViewComboBoxCell` 交互方式：点击“定额编号”组首单元格时创建并展开下拉；选择变化后提交编辑并刷新该 `TargetRow` 的完整预览组。增加 `DataError` 守卫，避免表格切换单元格类型时弹出未处理异常。

## 5. 状态与反馈

- 红色表示“精确同名但仍需人工确认”，不再表示“没有候选定额”。
- 单一绑定由用户勾选确认；多个绑定必须通过下拉选择确认。
- 未确认的红色组默认不进入写入集合，也不得写入对应框或模板学习数据。
- 已确认组继续沿用现有 `FilterFullyWrittenNameGroups`：只有整个组件实际写入成功后才反馈学习。
- 右键“绑定软件选中的定额到此行”继续可用，并继续原子替换当前 `TargetRow` 的完整组；右键重绑等同人工确认并取消红色。

## 6. 性能约束

- 不为每个表格单元格重复扫描模板；预览开始时一次构建“归一化名称 -> 绑定组列表”索引。
- 候选下拉项的显示文字在预览阶段预计算，点击时只创建当前行的下拉单元格。
- 切换候选只替换当前 `TargetRow` 的预览项，不重新读取 Excel、不重新加载项目定额和对应框文件。

## 7. 验证标准

至少覆盖以下回归：

1. 目标表两个“钢管 SC20 m”、模板仅绑定 `DY-959`：两处都显示 `DY-959`，初始红色且未勾选；确认后该目标组转为已勾选且取消红色。
2. 同名存在两个单定额绑定组：每个目标行定额列都有下拉，初始不为空；选择后只替换当前目标行。
3. 下拉候选包含 `DY-519 + ZLF*1.01` 组件组：选择后展开两条并共同勾选，不得拆组。
4. 同名只有一个组件组且目标重复：每个目标行都展开完整组件组。
5. 模糊最高分并列仍标黄，不进入精确同名下拉。
6. 数量为零的工程量仍直接丢弃。
7. 现有组件框整组写入、部分失败不学习、右键原子重绑、对应框整组回读测试继续通过。
