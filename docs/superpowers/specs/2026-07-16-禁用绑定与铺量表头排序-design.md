# 禁用绑定与铺量表头排序设计

## 目标

关闭“自动匹配 Excel 工程量”和“模板铺量”两个窗口中所有数据列的表头点击排序，避免误触后打乱软件生成的业务顺序。

## 范围

- `tools/RecoExpandPanel/AutoMatchFeature.cs` 中“自动匹配 Excel 工程量”预览表。
- `tools/RecoExpandPanel/TemplateFillPanel.cs` 中“模板铺量”预览表。
- 两个表格现有的全部列，以及以后在同一列初始化阶段加入的列。

不修改其他窗口的表格，不修改列顺序拖动行为，也不修改绑定、匹配、勾选、表达式、数量换算、铺量写入或数据保存流程。

## 方案

两个表格完成列创建后，逐列将 `SortMode` 设置为 `DataGridViewColumnSortMode.NotSortable`。这是 WinForms 原生的禁用排序方式，表头仍可正常显示，点击表头不再触发行重排，也不需要额外拦截点击事件或恢复排序状态。

采用各窗口本地设置，不新增公共抽象或配置项，保持修改范围最小。

## 行为要求

1. 两个窗口中点击任意列标题，行顺序保持不变。
2. 表头文字、列宽、选中行、复选框状态和当前编辑状态保持原有行为。
3. 自动匹配结果仍按现有生成顺序显示。
4. 模板铺量结果仍按现有生成顺序显示。
5. “单个绑定”“全部绑定”、手动匹配和模板铺量写入流程不受影响。

## 验证

- 增加针对两个表格全部列 `SortMode` 的回归检查。
- 运行现有“绑定 Excel 直达自动匹配”和“模板铺量”相关测试。
- 编译 `RecoExpandPanel.dll`，确认无新增编译错误。
- 进行窗口构造冒烟检查；条件允许时在实际软件中点击两个窗口的全部表头，确认行顺序不变。

## 风险控制

当前工作树存在本任务范围外的未提交修改。构建发布 DLL 时必须从已确认提交创建干净源码快照，只叠加本任务改动，避免将无关修改混入插件。目标软件进程未关闭时不覆盖其运行目录 DLL。
