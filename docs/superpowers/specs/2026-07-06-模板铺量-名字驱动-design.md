# 模板铺量·名字驱动匹配 — 设计文档

日期：2026-07-06
状态：设计已与用户讨论定稿，待写实施计划
承接：
- `2026-06-27-模板铺量-design.md`（v1，位置寻址）
- `2026-07-05-模板铺量-序列对齐-design.md`（模式一列锚点的行对齐，仍有效）
- 本对话已落地：**绑定Excel工程量时记录“工程量全名 → 定额编号”到推荐对应框 `mapping-boxes.jsonl`**
  （分支 `feature/bind-to-mapping-box`，`RecordBindingToMappingStore` / 不截断 `ReadRowNameAt(...,true)`）。

## 1. 背景与核心转变

v1 及序列对齐版都以**单元格位置**为取数根据。当源/目标行结构差异大、或目标其实是本单元另一个同结构条目时，位置寻址力不从心。

**核心转变**：把“工程量名字 ↔ 定额”作为第一等的对应关系。名字来自绑定（现已记全名并写入对应框），
于是模版铺量与推荐定额汇合成一条**名字驱动管线**：模版从“坐标快照”升级为“会学习的 名字→定额 清单”，
套用时按名字匹配数量、用推荐引擎补全未知量，匹配结果回喂对应框和模版，越用越准。

## 2. 范围

### 在范围内
- 模版**生成**新增“按名字”一种（与现有“按位置”并存，二选一）。
- 套用**模式二**由“固定绑定列”**彻底替换**为“名字驱动匹配”。
- 名字驱动套用：预览以 Excel 工程量为主序；未匹配量特殊标记；推荐引擎自动挂定额；
  空定额框可调候选框手工挂；未匹配量支持**一量对多定额**（新增定额行）；匹配回写对应框 + 模版。
- 想法二：预览章节树右键**复制本条目匹配到的定额 → 目标条目选择器 → 直接写库**（可本单元/别单元，结构相同）。

### 不在范围内 / 明确删除
- **删除“固定绑定列”模式二**（连同其 `BuildPreview_FixedColumn`、UI 选项、相关文案）。
- 不做系统剪贴板逆向（想法二取方案 A，走直接写库，不碰软件原生剪贴板格式）。
- 一量对多定额（组件框）**只对“未匹配/新增”工程量开放**；已由模版命中的量保持原样，多数量本就一对一。
- 模式一（列锚点 + 序列对齐）行为不变，仅共用底层零件。

## 3. 模版数据模型：两种生成模式

模版加 `MatchBy` 字段：`position`（现有）| `name`（新）。`FillTemplateRow` 扩展：

```
FillTemplateRow {
  ItemNo / QuotaCode / Adjust / OrderInItem / SourceQuotaSeq   // 不变，写入仍整行复制源定额行
  SourceSheet / SourceExpr                                     // position 模式用
  SourceName        // 现为截断显示名 -> 名字模式改存【全名】(不截断)
  Operands[]        // 名字模式且表达式时：每个操作数 { Name(全名), Op(+/-/*/等), Literal(如 *1.5 的 1.5) }
}
```

- **position 模式**：现状，harvest 绑定的 sheet+cell，套用按列锚点/对齐取数。
- **name 模式**：harvest 绑定，但每行改记**该行工程量全名 + 定额 + 条目 + 顺序**。
  表达式如 `E1+E2`：生成时读 E1、E2 各自所在行的全名，存为 `Operands=[{"E1行全名","+"},{"E2行全名","+"}]`，
  **不再绑死 E1/E2 坐标**。套用时按名字在目标里各自定位，取到数量再按算子合成。

## 4. 套用两模式

- **模式一·列锚点**：不变（含 `2026-07-05` 的序列对齐纠偏、新增行识别）。
- **模式二·名字驱动**（替换固定绑定列）：见 §5。面板“取数模式”下拉去掉“固定绑定列”，改为“名字驱动”。

## 5. 名字驱动套用流程

1. 选 name 模式模版 + 模式二 + 目标 sheet（点目标数量列任一格拿 sheet+列）。
2. **快照目标 sheet**（复用序列对齐版的整表 `UsedRange` 一次读 + 行指纹，`GetRowAlignText`/不截断名字）。
3. **以 Excel 工程量行为主序**遍历目标表每个“有数量”的工程量行：
   - **a. 模版命中**：该行全名 ↔ 模版某行（章节内就近，复用对齐引擎归一化+bigram 打分）→ 直接取该行定额、条目、数量。
   - **b. 推荐命中**：模版没有 → 走推荐引擎自动匹配（§7），给出候选，高分预填、低分留空。
   - **c. 未命中**：留空、标黄，等用户在候选框手挂。
   - 表达式操作数：逐个操作数名字在目标就近定位取数，按算子合成表达式与数量。
4. **条目落位**：模版命中的量用模版记的条目；仅推荐/手工命中的量落“上方最近已匹配行的条目”，**可由用户改选**（想法二的目标条目选择器同一控件）。
5. **预览**：
   - 点“全部”：按 **Excel 工程量行顺序**平铺（不是按条目）。
   - 点具体章节条目：只显示落在该条目下的内容（沿用现有树筛选）。
   - 三色分诊：白=模版/高分命中；黄=推荐建议待核 / 未匹配待手挂 / 条目落位为推断；红=数量为空/读失败。
   - 未匹配量明确标“无对应定额”，并给手挂入口。
6. **写入**：复用现有 `ApplyFill` 整行复制路径；名字模式下数量来自目标表按名字取到的值。撤销纳入现有栈。

## 6. 未匹配量的手工挂定额（含一量对多）

- 预览里“空定额”行双击 → **定额候选框**（复用推荐候选框交互）：先显示推荐 top-N，可按编号/名称搜索。
- **可“新增定额行”**：一个未匹配工程量允许挂 **多条**定额（组件框语义）。仅对未匹配/新增量开放；已由模版命中的量不提供此入口。
- 选定（一条或多条）后：
  - 该量在预览中展开为多行定额（组件框第一行承载工程量名，其余留空——与推荐插件组件框 UI 规则一致）。
  - 条目落位默认邻居、可改选。
- 见 §8 回写。

### 6.1 手挂升级（2026-07-13 用户追加，已定）

- **候选两池合一**：项目内定额（`定额输入` 去重，可整行复制写入）＋**全库** `quota-index.jsonl`
  （字段 quota_code/quota_name/quota_unit，文件读，不跨 DLL 调代码）。库内条目在列表中带“库”标记；
  搜索两池同搜，项目内优先排序。原“项目内无匹配则只能去软件录入”的一期边界取消。
- **选完定额选条目**：候选框下半区加“放入条目”搜索列表（`章节表` 全量：条目序号/条目编号/名称，
  面板会话内缓存），默认预选邻居推断条目。产出 `ChosenItemSeq/ChosenItemNo`，写入优先于邻居锚点；
  “无条目锚点”行由此解锁（显式选条目即可写）。
- **写入分流**：
  - 项目内定额 → 现有直接整行复制路径，`条目序号` 用用户选的。
  - **库内定额（项目无此编号）→ 原生粘贴管线** `ExecuteAgentInsertGroup`（智能指令同款：
    导航到条目、剪贴板粘贴“编号+数量”、软件原生补齐名称/单位/单价，撤销走 before/after 差集并入本次 undo）。
    **约束**：粘贴写的是软件当前单元，要求 目标单元==GetCurrentUnitNo，不符则该行提示跳过。
    符合 AGENTS.md“能用软件原生写入的尽量用原生写入”。
- 回写（§8）同样覆盖库内手挂结果。

## 7. 自动匹配的数据来源（跨 DLL 架构决策）

现状：模版铺量在 `RecoExpandPanel`，推荐引擎在 `RecoQuotaRecommend`，两 DLL **只通过共享文件互通，不互调代码**。

- **主来源 = 共享 `mapping-boxes.jsonl`**（本对话的绑定写入口正在持续喂它）：RecoExpandPanel 直接读该文件、
  用自带归一化 + bigram 打分给候选。自洽、无跨程序集脆弱性、直接吃绑定飞轮。**v1 采用此路。**
- **增强（可选）= 反射调 `RecoQuotaRecommend` 全引擎**：在 `QuotaRecommendPanel` 暴露稳定
  `public static` 入口（如 `RecommendForQuantity(name, unit)` 返回候选），RecoExpandPanel 反射调用，
  复用带 quota-index 全库检索 + 钢筋/混凝土等领域规则的完整排序。质量更高但需维护跨插件签名。
  **列为二期**，先不阻塞。

## 8. 回写：匹配结果 → 对应框 + 模版

匹配成功（自动被接受或手工挂定）后，双写：

- **写推荐对应框**（`mapping-boxes.jsonl`）：全名 → 定额（一条或多条=组件框多 target），复用 `RecordBindingToMappingStore`
  的 schema/锁/去重加权路径（本对话已建）。多定额时写多 target。
- **写回该模版**：把“全名 → 定额(+条目+顺序)”补进当前 name 模式模版，使模版本身越用越全（下次同名直接模版命中）。

## 9. 想法二：条目级复制到目标条目（直接写库，方案 A 已定）

**为何不用剪贴板**：软件粘贴格式只认“定额编号 + 工程数量”两列（`BuildTabSeparated` / `ExecuteAgentInsertGroup` 实测均如此），
**带不走 `定额调整`（换算/系数/工料调整）**。想法二要复制的定额**普遍带换算/系数且必须原样保留**，
故剪贴板方案不可用；采用**直接写库整行复制**（`ApplyFill` / `LoadTemplateFullRow` 复制整行，天然保留换算/系数/单价）。

预览章节树**右键菜单**加“复制本条目匹配到的定额”：

- 收集该条目下的定额行（含名字驱动匹配结果与其 `定额调整` 快照）。
- 弹**目标条目选择器（多选）**：目标条目由用户直接指定，**编号与源不同是常态**。目标可为
  **同级兄弟条目**（如 `0305-01-01`→`0305-01-02`）、**下级/子条目**、或**别单元的条目**；一次可选多个目标（fan-out 复制）。
- **直接写库**：复用 `ApplyFill` 整行复制，`条目序号`→用户选定的目标条目、`总概算序号`→目标条目所在单元、
  `顺号`=目标条目内 max+1，`定额调整` 等整行带过去。撤销入栈。
- **源节点范围**：v1 以“选中的叶子条目”为源；选中含子条目的父节点时的处理见 §10 待定项。
- 意义：目标既可别单元，也可本单元的并列条目**或下级子条目**——覆盖想法二诉求。

## 11. 边界与风险

- **名字读取质量是名字驱动的命门**：全名读取（不截断 + 合并区域回填）必须稳；脏表缺名的行会落进“未匹配”手挂通道（保命层，须顺手）。
- **同名歧义**：章节内就近能挡大多数；跨章节重复名靠章节锚点分段隔离（复用对齐引擎）。
- **模版回写膨胀**：同一模版反复回写需按“全名+条目”去重，避免同一映射重复堆积。
- **跨 DLL 反射（二期）脆弱**：签名须稳定；v1 不依赖它，仅共享文件。
- **想法二父节点源（待定项）**：目标条目用户直接选定（多选，含下级子条目）、编号可与源不同——这些已定。**唯一待定**：当右键的源节点是含子条目的父节点时，是“把其全部子孙定额拍平复制到目标”还是“提示改选具体子条目”。二期实施前确认。
- C# 5 语法、UTF-8 BOM/`\u` 转义、写库失败不得影响主流程——沿用 AGENTS.md 既有约束。

## 12. 验收要点

1. name 模式模版：源单元绑定后生成，表达式行正确存操作数名字。
2. 名字驱动套用：目标表增删/改名行不影响按名取数；预览按 Excel 行序；未匹配量标黄可手挂。
3. 一量对多：未匹配量手挂多条定额，写入后组件框正确、对应框写多 target、模版回写。
4. 条目落位：推荐命中量落邻居条目且可改选。
5. 想法二：右键复制某条目定额 → 选本单元另一同结构条目 → 写入正确、撤销可回滚。
6. 固定绑定列相关代码/UI 已删净，模式一（含序列对齐）回归不受影响。
