# 工程量学习库(RecoLearning)与自动铺定额 设计文档

日期:2026-07-18
状态:已与用户确认方向,待实施

## 1. 背景与目标

Excel 绑定、模板铺量、推荐窗口扶正等功能中,用户已人工建立了大量"工程量 ↔ 定额(组) ↔ 所在条目"关系,但这些知识分散且量小:

| 现有资产 | 规模 | 问题 |
|---|---|---|
| mapping-boxes.jsonl | 46 条 | 只靠日常绑定慢慢攒,本机文件 |
| learning.jsonl | 23 条 | 同上 |
| chapter-quota-library.jsonl | 11.6 万条(2020:6.8万 / 2024:2.3万 / 101概算:2.5万) | 只有"条目→定额",无工程量名 |
| chapter-entries.jsonl | 1.2 万条 | 章节条目树,现成 |
| ExcelLinks/*.xml | 4 个项目 | 最完整的三元组(工程量名+定额+章节位置),未收割 |
| 服务器 430+ 项目库 | 海量 | 完整条目→定额→数量结构 |

**目标**:把这些知识汇入一个集中、带索引、可持续生长的学习库;学习库成熟后,读一张 Excel 工程量表即可自动生成项目的定额铺量,人工只处理低置信度部分,且每次人工纠正自动回流学习库。

## 2. 总体架构

### 2.1 三层知识分离(防数据爆炸)

专业提来的工程量表五花八门(格式、合并单元格、命名习惯各异)。应对方式是不存"记录"、存"知识",三层分离:

1. **别名层**:原始工程量名 → 归一化签名(去空格、全半角统一、提取规格参数)。同一签名重复出现只加计数不加行,行数收敛于真实叫法数量。
2. **映射层**:签名 → 定额组(box,一个"做法"的定额/辅助/材料集合)。多个签名可指向同一 box。全路标准做法量级为数千。
3. **条目层**:定额组放哪个条目由上下文决定(工作表工程类型 + 条目定额共现概率),不与名称映射绑死。"同名同定额但放不同条目"因此不产生组合爆炸。

### 2.2 工程模板(表级先验)

一个工作表往往对应一个特定工程(桥梁、路基、轨道、房建、站场等)。同一工程的工程量名称因提供人习惯而异,但对应定额和条目不变。

**工程类型由条目编号前缀自动归集**(如桥梁条目为 03 开头),从日常绑定数据的 entry_code 中自然积累,无需人工建模板。匹配时先识别工作表的工程类型,再在该类型模板范围内优先匹配。

### 2.3 匹配漏斗(生成时)

```
Excel 工程量行
  ↓ ① 签名精确命中学习库(毫秒,主路径)
  ↓ ② 归一化/规格参数/同义词规则匹配
  ↓ ③ 大模型语义匹配(调用现成模型,不自建训练;插件已接 DeepSeek)
  ↓ ④ 低置信度留给人工,在软件里扶正 → 结果回流学习库
```

不训练专用大模型:样本量不足、办法更新即过时、成本高且黑盒。漏斗 + 回流使自动化比例随使用逐月上升。

## 3. 数据层:RecoLearning 库(SQL Server,192.168.2.213)

事实与知识分开:流水表只增不删,聚合表可由流水重算(定期整理 = 重跑聚合)。

| 表 | 内容 | 关键字段 |
|---|---|---|
| 绑定流水 BindingLog | 每次绑定/扶正/铺量事件,追加式 | 来源(自动绑定/模板铺量/新窗口/收割)、项目、raw_name、quota_code、entry_code、时间 |
| 工程量别名 QuantityAlias | 原始名 → 签名 | raw_name、signature、spec_params、unit、seen_count |
| 定额组 QuotaBox / 明细 QuotaBoxTarget | 一个做法的目标集合 | box_id;kind(quota/aux/material)、code、name、unit |
| 签名映射 SignatureBoxMap | 签名 → box | weight、accepted/corrected/rejected 计数、last_used_at |
| 条目定额共现 EntryQuota | 条目 → 定额 | method、entry_code、quota_code、project_count(导入现有 11.6 万条) |
| 章节条目 ChapterEntry | 条目树 | method、entry_code、entry_name、level(导入现有 1.2 万条) |
| 工程模板归集 EngineeringTemplate | 工程类型 → 条目/box | engineering_type(按 entry_code 前缀,如 03→桥涵)、entry_code、box_id、sample_count |

- 归一化签名算法与插件 `NormalizeForSignature` 同款,保证两端一致。
- 索引:signature、quota_code、(method, entry_code)、engineering_type。
- 坏知识不删除,用 rejected 计数压权重。

### 写入方(四路汇入)

1. 自动绑定 Excel(现写 mapping-boxes.jsonl 处增加 SQL 双写,失败不影响绑定本身)
2. 模板铺量名字匹配(同上)
3. 新智能铺量窗口的手动扶正
4. Claude 存量收割与定期整理

学习库定期导出同步回 mapping-boxes.jsonl,现有插件推荐功能照常受益。

## 4. 界面层:智能铺量窗口(C# 插件)

改造推荐定额窗口,布局参考模板铺量窗口:

- **上部**:目标 Excel、目标 sheet、目标列、目标单元、预览、写入目标单元
- **下部**:左侧条目目录,右侧预览窗口
- 打开工作表后:识别工程类型 → 走匹配漏斗 → 预览区按"自动匹配 / 待确认"两档展示(工程量 → 定额组 → 目标条目 → 置信度)
- **手动扶正**:对出错或未匹配的行,在软件定额输入中选中定额,左键点预览窗口中该工程量 → 完成绑定,并记录进学习库

## 5. Claude 的职责

1. **建库与存量收割**(一次性,可重跑):收割 4 个 ExcelLinks XML(其中 ChapterSeq 回连对应项目库解析为标准条目号)、mapping-boxes、learning.jsonl、两个 jsonl 大库;出统计报告。
2. **定期整理**(用户召唤):合并别名、压制坏映射、重跑模板归集、对账 jsonl 同步。
3. **盲考评估**:取已完成的历史项目,用其原始 Excel 工程量表跑匹配,与人工成品逐行对比得出命中率,作为学习库质量基线。
4. (过渡期)直接写项目数据库生成铺量:用户在软件新建空项目并关闭 → Claude 读 Excel 走漏斗 → 出预览清单供确认 → 备份数据库后写章节表/定额输入(生成行打批次标记,可整批回滚)→ 用户开软件重算验证。派生表(工料机、劳材汇总等)由软件重算生成,不直接写。

## 6. 实施分期(每期独立可用)

- **一期:数据层**——建 RecoLearning 库;存量收割;插件现有两条写入路径(自动绑定、模板铺量)增加 SQL 双写。完成后学习库开始持续生长。
- **二期:智能铺量窗口**——改造推荐定额窗口,读学习库走漏斗,预览/写入/手动扶正回流。
- **三期:工程模板与治理**——表级工程类型识别、模板内优先匹配、整理与盲考工具。

## 7. 安全与错误处理

- 写项目库前先 `BACKUP DATABASE`;生成行带批次标记,支持整批回滚。
- 双写失败只记日志,不阻断绑定/铺量本身(沿用现有"写库失败不得影响绑定"原则)。
- 学习库流水只增不删;聚合可随时由流水重算,整理操作可审计。

## 8. 验收标准

- 一期:收割后 SignatureBoxMap ≥ 千条量级;插件绑定一次,SQL 与 jsonl 同时可查到该记录。
- 二期:对一张真实工程量表,窗口能完成"匹配→预览→写入→扶正回流"闭环。
- 三期:盲考命中率有基线数字,且回流后重跑盲考可见提升。
