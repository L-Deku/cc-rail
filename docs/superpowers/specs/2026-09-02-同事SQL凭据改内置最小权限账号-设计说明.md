# 同事机器访问 SQL 学习库：改为"插件内置最小权限账号 + 软件目录配置文件"

日期：2026-09-02
状态：代码已实施并通过本地测试；服务器建号与实机验收待用户执行。

## 1. 背景与拍板

此前（codex 实施）同事端凭据用 DPAPI CurrentUser 绑在每个 Windows 用户下，跨机器靠"加密包 + 独立渠道验证码"或"一次性 RSA 公钥"传递，每台电脑约 9 步、两个渠道，没有更新/换密码路径，且只覆盖 `RecoExpandPanel.dll`。

两个事实让这套复杂度不值：
- `RecoQuotaRecommend\SearchIndexStore.cs` 一直硬编码 `reco` 账号与拼接混淆的密码并随发布包分发，"密码不出本机"的前提早已不成立。
- 同事同时使用 2024 客户端（宿主连 .213）和 2020 客户端（宿主连 .13），"借宿主连接"只能覆盖一半人。

用户 2026-09-02 拍板：
1. 在 .213 与 .13 各建最小权限专用登录名 `reco_plugin`，插件只用它。
2. 凭据以软件根目录的 `RecoPluginSql.json` 随发布包分发，固定应用口令封装仅防目视；换密码只换这一个文件。
3. 同事零步骤。
4. 推翻 08-05 "发布包不含凭据"的决定，但发布包只允许含 `reco_plugin`；`reco`、个人 DPAPI 文件、任何一次性密文包仍禁止。

宿主软件自己的登录与项目读写不受影响；插件写当前项目仍借宿主连接。

## 2. 权限模型

| 服务器 | 库 | 角色 | 用途 |
|---|---|---|---|
| .213 | RecoLearning | db_datareader + db_datawriter | 绑定流水/聚合写入、推荐读取 |
| .213 | RecoData2024、RecoData2020 | db_datareader | 推荐定额索引/材料库刷新。正式目录的 2020 宿主 `ServerSetting.xml` 也指向 .213，且 .213 上有一份 RecoData2020（guest 可连、无读权限），漏授会报"拒绝 SELECT 材料单价库" |
| .13 | RecoData2020、RecoData2024（若存在） | db_datareader | 同上，连 .13 的 2020 宿主 |
| .213 与 .13 | 现有各用户库（项目库） | db_datareader | 跨库整行复制的只读溯源 |
| .213 与 .13 | model | db_datareader | 新建项目库自动继承只读 |
| 两台 | 服务器级 | 仅 CONNECT | 不属于任何服务器角色 |

脚本：`tools\RecoCredential\sql\Create-RecoPluginLogin-213.sql`、`Create-RecoPluginLogin-13.sql`（SQLCMD 变量 `PluginPassword` 传密码，幂等）、`Diagnose-RecoLogins.sql`（只读核对）。由用户在 SSMS 手工执行。

## 3. 文件格式：`RecoPluginSql.json`

信封（JSON，字段值只含 Base64/GUID/数字）：

```
version=1, package_type="plugin_sql_config", package_id, iterations, salt, iv, ciphertext, mac, created_at_utc
```

- 密钥：PBKDF2-SHA1(固定口令常量, salt 16 字节, iterations 默认 20000) → 64 字节，前 32 AES-256-CBC，后 32 HMAC-SHA256。
- MAC 输入：`RecoBudget.CredentialTransfer.v1\n` + `plugin-sql-config|package_id|iterations|salt` + `\n` + iv + ciphertext；先验 MAC 再解密。
- 明文与 DPAPI 凭据库同格式：`version=1` 加 `learning.server/user/password`、`business.server/user/password` 六个 Base64 行。
- 口令常量同时定义在 `RecoShared\RecoSqlCredentialStore.cs`（`PluginConfigPassphrase`）与 `tools\RecoCredential\RecoCredentialTransfer.ps1`（`$script:RecoPluginSqlConfigPassphrase`），改一处必须同步另一处并跑 `tests\Test-RecoPluginSqlConfig.ps1`。

## 4. 读取端行为（`RecoShared\RecoSqlCredentialStore.cs`）

- `Read(name)`：程序集同目录存在 `RecoPluginSql.json` → 解密使用；否则回退当前 Windows 用户 DPAPI 凭据库。环境变量 `RECO_PLUGIN_SQL_CONFIG_PATH` / `RECO_SQL_CREDENTIAL_STORE_PATH` 供测试覆盖。
- 配置文件中任一登录名为 `reco` 直接抛错。
- `BuildConnectionStringForServer(server, database, port, timeout)`：按主机部分（忽略端口）在 learning/business 两条记录里路由，与 `tools\RecoLearning\Common.ps1` 同规则。
- `SearchIndexStore.cs` 的两处硬编码改为 `BuildConnectionStringForServer(ReadServer(), ...)`；`ServerSetting.xml` 读不到地址时报错，不再回退 `127.0.0.1`。`build.ps1` 已把 `RecoSqlCredentialStore.cs` 并入 `RecoQuotaRecommend.dll`。
- 离线工具（`SupplementQuotaSectionFix`、`ChapterQuotaLibrary`、`Migrate2020EstimateTo2024`）程序集目录没有配置文件，行为不变，继续用管理员 DPAPI 的 `reco`。
- 用户本机的正式目录与 2020 历史目录也不放 `RecoPluginSql.json`（2026-09-03 用户决定），本机插件同样走 DPAPI 的 `reco`；`build.ps1` 部署时会清掉残留的配置文件。09-03 实机验收时本机曾临时放入配置以 `reco_plugin` 身份验证：BindingLog 写入 10 条、2024/2020 定额库刷新均通过。

## 5. 生成与发布

- 生成：`tools\RecoCredential\New-RecoPluginSqlConfig.ps1`。默认 `learning=192.168.2.213,1433`、`business=192.168.2.13,1433`、`User=reco_plugin`，`Read-Host` 读密码；生成前连三个端点核对（RecoLearning 需 SELECT+INSERT+UPDATE，RecoData2024/RecoData2020 需 SELECT，实际登录名须等于 `reco_plugin`），任一失败不落盘；输出 `RecoQuotaRecommend\bin\RecoPluginSql.json`（`bin/` 已被 .gitignore 忽略）。
- 发布：`tools\BuildColleaguePluginRelease.ps1` 解开并校验该文件（登录名非 `reco`、端点分别为 .213/.13），复制到 `00-首次安装公共包` 与 `90-后续更新文件\公共组件更新`；删除了三个 `SQL凭据*` 子目录与全部凭据脚本；`使用说明.txt` 首次安装回到 4 步。
- 已移除的死路径（未曾提交，备份在会话 scratchpad）：`Generate-RecoCredentialImportKey.*`、`New-RecoEncryptedCredentialPackage.ps1`、`New-RecoOneTimeCodeCredentialPackage.ps1`、`Import-RecoEncryptedCredentialPackage.*`、`Import-RecoOneTimeCodeCredentialPackage.*`、两个对应测试。`RecoCredentialTransfer.ps1` 只保留共用加密核心与插件配置函数。

## 6. 上线顺序

补充事实（2026-09-02 只读探测）：两台服务器均为 SQL Server 2008 R2（10.50.6000），本机 DPAPI 里的 `reco` 在两台上都是 sysadmin。因此建号不必依赖 SSMS/sa。

1. 用户双击 `tools\RecoCredential\一键建立插件SQL账号.cmd`（`Invoke-RecoPluginLoginSetup.ps1`）：输入两遍新密码 → 用 DPAPI 的 `reco` 连两台服务器执行 `Create-RecoPluginLogin-213.sql` / `-13.sql` → 核对登录名存在、无服务器角色、所有用户库都有 `reco_plugin` 用户 → 直接调用 `New-RecoPluginSqlConfig.ps1` 生成配置文件。有 SSMS 的话也可以按 §2 手工跑 .sql。
2. （手工路径才需要）本机运行 `New-RecoPluginSqlConfig.ps1`，输入 `reco_plugin` 密码，三个端点 PASS。
3. `build.ps1` 构建并部署到正式目录；把 `RecoPluginSql.json` 复制到正式软件根目录；2024 宿主绑定一条定额 → `RecoLearning.dbo.BindingLog` 新流水、`RecoExpandPanel.log` 无凭据错误；2020 宿主触发材料库刷新 → `RecoQuotaRecommend.log` 读取 .13 成功。
4. `BuildColleaguePluginRelease.ps1 -Force` 生成发布包，发给同事。
5. 同事端验收：软件根目录有 `RecoPluginSql.json`，同事 `RecoExpandPanel.log` 无凭据错误，BindingLog 出现其绑定流水。

## 7. 后续：轮换 `reco`

同事全部切到新包后，在两台服务器 `ALTER LOGIN [reco] WITH PASSWORD = ...`，然后删除本机 `%LOCALAPPDATA%\RecoBudget\Secrets\sql-credentials.dpapi` 并重跑 `tools\RecoCredential\Initialize-RecoSqlCredentialStore.cmd`。届时旧 DLL 里的硬编码密码彻底失效。
