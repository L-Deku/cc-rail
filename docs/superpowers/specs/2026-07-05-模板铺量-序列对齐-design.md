# 模板铺量·序列对齐升级 — 设计文档

日期：2026-07-05
状态：设计已与用户讨论定稿
前置：`2026-06-27-模板铺量-design.md`（已落地的模板铺量 v1）

## 1. 背景与问题

模板铺量 v1 的取数是**位置寻址**：模板记 `sheet + 行号`，模式一换列/换 sheet 后沿用行号逐格读数。
当目标 sheet 相对源 sheet **多行/少行/改名**时，同一行号不再是同一工程内容，v1 只能靠预览
"名称核对标红"事后报警，用户需手工排查，无法自动纠偏，也无法处理目标表新增的工程量行。

**核心思路**：行的身份是内容不是行号。把源表行序列与目标表行序列做 diff 式**序列对齐**
（章节锚点分段 + 段内 Needleman-Wunsch），行号降级为先验。类比 git 补丁的上下文行机制。

## 2. 范围

### 在范围内（一期，本设计）
- **仅模式一（列锚点）**增加"自动对齐"能力（默认开启，可关闭回退 v1 行为）。
- 整表快照读取（一次 COM `UsedRange.Value2` 拉取，替代逐格名称读，预览应更快）。
- 章节锚点分段 + 段内序列对齐 + 疑似改名识别。
- 目标表新增行：识别、预览黄标、条目归属推断（跟随上方最近匹配行）、
  项目内定额候选推荐（按名称相似度 top5）+ 双击弹窗搜索选择。
- 新增行写入：**整行复制项目内同编号定额行**，`条目序号` 改挂邻居条目，`定额调整` 清空，
  预览注明"调整请写入后核对"（用户已确认接受此简化）。
- 模板缺失行（源有目标无）：标"目标行缺失"跳过。

### 不在范围内（明确排除 / 二期）
- 模式二（固定绑定列）不动——它本来就是人工对齐的兜底通道。
- 不改模板 JSON 结构（源指纹在套用时从源 sheet 快照现算，旧模板零迁移）。
- 学习库（mapping-boxes/quota-index）推荐、LLM 兜底、Excel 身份证列 —— 二期。
- 项目内不存在的定额编号：新增行不写入（留空提示手工在软件输入），不从定额库造基础行
  （避开"直接设值不触发派生字段填充"的坑，见 AGENTS.md UI 行为规则）。
- 新增行不自动勾选；即使有高分推荐也必须用户确认后手工勾选。

## 3. 数据流

```
套用(模式一+自动对齐):
  用户点目标列一格 → 快照源sheet + 目标sheet（COM 按路径找已打开工作簿，UsedRange 整读）
  → 双侧构建行指纹（数量列前全部非纯数字单元格全文拼接，合并区域锚点回填，不截断）
  → 锚点分段（"一、/（一）/第X章"正则）→ 段内 NW 对齐（bigram Dice 相似度，
     文内数字不符重罚，锚点行不参与条目配对）→ 剩余行段内宽松互撮=疑似改名
  → 模板行按对齐结果平移取数表达式行号（ShiftExprRows）→ 复用既有 BuildPreview 取数
  → 目标侧剩余带数量行 = 新增行，插到邻居匹配行之后，推荐项目内定额候选
  → 预览三色分诊：无异常=白 / 疑似改名·新增=黄 / 缺失·取数失败=红
  → 写入：匹配行走 v1 整行复制路径；新增行复制 ChosenQuotaSeq 行 + 改条目序号 + 清调整
```

快照要求工作簿已在 Excel/WPS 打开（模式一流程本身要求用户在打开的表里点目标列，天然满足）；
快照失败时自动回退 v1 位置寻址并弹提示。

## 5. 关键决策与理由

- **指纹套用时现算而非存进模板**：旧模板直接受益，无迁移;代价是源 sheet 必须可读，读不到就回退。
- **显示名与匹配指纹分离**：显示仍用 15字/3段 的 `GetQuantityNameForCell`（与自动匹配一致，
  AGENTS.md 要求两功能名称规则统一）；匹配用不截断全文。
- **新增行条目归属跟邻居**：用上方最近匹配行的 `SourceQuotaSeq` 在写入时取 `条目序号`，
  完全避开对 `章节表` 结构的新依赖。
- **新增行只复制项目内已有定额行**：写入路径与 v1 完全同构（`LoadTemplateFullRow` → 改字段 → 插入），
  单价/消耗天然正确;调整清空留人工，符合已确认的简化。
- **合计/小计行不算新增行**（归一化文本以 合计/小计/总计 开头的排除）。
- **相似度**：字符 bigram Dice(0-100)；双方都含数字且数字集不相交时得分 /3；
  匹配阈值 55，改名阈值 35，gap 罚 40，match 基准 -50。阈值为常量，便于调。

## 6. 边界与风险

- 表达式跨行（如 `E4+E5`）按首格行号的偏移整体平移；若插行恰好落在 E4、E5 之间会错，
  由名称核对红标兜底（与 v1 同级风险，不恶化）。
- 纵向合并区域的子行指纹含锚点文本+本行碎片；若整段子行文本完全相同，段内按顺序对齐（NW 天然保序）。
- Excel 未保存时快照值来自 COM 而合并区域来自磁盘文件，沿用现有"先保存再匹配"的假定（AGENTS.md 已有此规则）。
- C# 5 语法约束、新增中文字符串编码规则（UTF-8 BOM / \u 转义）遵守 AGENTS.md 代码编辑规则。

## 7. 验收

1. 目标 sheet 中部插 2 行删 1 行：预览全部行名称核对通过、无错位红标；关掉自动对齐可复现 v1 错位。
2. 同名条目分属两个章节（如两处"混凝土"）：各自在本章节内对齐，不串段。
3. "铺设无缝线路"↔"无缝线路铺设"：识别为同一行（直配或疑似改名黄标）。
4. 目标表新增一行带数量工程项：黄标"目标表新增"，落在正确条目下，双击可选项目内定额，
   写入后定额挂对条目、数量正确、可撤销、"计算"后单价正常。
5. 模式二行为与 v1 完全一致；快照失败时回退 v1 并提示。
6. PowerShell 反射冒烟：对齐引擎 6 组合成用例全过（等长/插行/删行/改名/数字不符/跨章节同名）。
