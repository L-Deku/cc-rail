# 模板铺量 Excel 读取性能优化设计

## 背景

2020 与 2024 主程序加载的是同一版 `RecoExpandPanel.dll`，性能差异主要来自工作簿体量和运行状态，而不是两套不同的模板铺量逻辑。当前 2024 绑定集中在一个约 4.6 MB、17 个工作表的 `.xlsx` 文件中；现有热路径会反复让 NPOI 解析整个工作簿，因此“按名称生成模板”、打开模板铺量窗口和右键交互都可能阻塞界面线程。

本次只优化模板铺量的 Excel 读取和窗口初始化热路径，不改变业务结果和主体功能。

## 目标

- 按名称生成模板时，同一批绑定只建立一次共享读取上下文，避免按行、按单元格重复解析同一工作簿。
- `.xlsx`/`.xlsm` 保存文件优先使用现有的定点 XML 读取器，只读取本批次需要的单元格；失败时无损回退到原 NPOI 路径。
- 模板铺量窗口首次构造时只枚举一次目标工作簿，消除模板下拉框初始化触发的重复枚举。
- 保持现有模板、匹配、单位换算、表达式计算、原生写入和异常回退行为不变。

## 非目标与边界

本次不修改：

- 定额或材料匹配规则、排序、同名候选确认和右键临时绑定语义；
- 模板 JSON 结构、绑定存储格式和用户数据；
- 单位扫描、数量换算和表达式语法；
- 软件原生写入、数据库连接、智能指令和定时同步线程模型；
- `.xls` 文件读取方式；
- 运行目录之外的任何文件。

本轮不把 Excel 同步整体改成后台线程，也不缓存跨操作的工作簿对象。这样可以避免引入 COM 线程、文件变更失效和对象生命周期风险。

## 方案

### 1. `.xlsx` 定点读取优先，NPOI 保底

`ExcelSyncReadContext.LoadFileSheet` 已经一次性知道当前批次需要读取的地址集合。对 `.xlsx` 和 `.xlsm`：

1. 先调用现有 `TryReadXlsxTargetCells`，从压缩包中的工作表 XML、共享字符串和样式信息读取目标单元格；
2. 若定点读取失败，再调用现有 `TryReadSheetTargetCellsByNpoi`；
3. 两条路径都失败时，维持现有错误汇总方式；
4. 对 `.xls` 直接保持原 NPOI 路径。

这不是新增解析器，而是调整两个已存在读取器的优先级。回退保证不支持的文件结构仍按原逻辑工作。

### 2. 按名称生成模板共享批量读取上下文

`BuildNameFillTemplateFromBindings` 当前在读取主表达式名称和组合表达式操作数名称时，多次调用 `ReadFullNameForCell`；后者每次都为少量链接创建新的 `ExcelSyncReadContext`。

调整为两阶段处理：

1. 先收集本次模板全部源表达式和操作数中的单元格引用，构造完整 `readLinks`；
2. 用该集合创建一个共享 `ExcelSyncReadContext`；
3. 再逐行生成 `MatchName` 和操作数 `Name`，全部复用这个上下文；
4. 隐藏列与合并区域缓存仍沿用当前批次缓存；名称拼接、去重和排序规则不变。

只改变读取次数，不改变模板行、表达式、名称和保存结果。

### 3. 窗口初始化只枚举一次工作簿

当前构造函数在 `ReloadTemplateList` 设置模板选中项时会触发 `SelectedIndexChanged`，从而调用一次 `ReloadTargetWorkbooks`；构造函数随后又显式调用一次。

增加仅覆盖初始化阶段的事件抑制状态：

- 初始化模板列表期间，不响应模板选择变化触发的目标工作簿刷新；
- 初始化完成后，构造函数显式刷新一次；
- 用户之后切换模板时仍按原逻辑刷新；
- 目标工作簿显示文本、选择保留和工作表刷新行为不变。

## 数据流

```text
绑定/模板行
  -> 收集本批所需工作簿、工作表、单元格
  -> ExcelSyncReadContext
       -> xlsx/xlsm 定点 XML 读取
       -> 失败时回退 NPOI
       -> xls 继续使用 NPOI
  -> 现有名称拼接、表达式计算和模板保存逻辑
```

## 异常与兼容性

- 定点读取异常不会直接终止操作，而是回退到 NPOI。
- NPOI 仍是旧 `.xls` 的唯一保存文件读取路径。
- 已打开且可从 COM 读取的工作簿仍遵循现有实时读取优先级，本方案只优化保存文件读取上下文内部路径。
- 不持有跨操作缓存，文件保存后下一次操作会重新读取，不产生陈旧数据。
- 不改变空单元格、公式缓存值、日期/数值格式和错误文本的上层处理约定；以回归对比结果作为合入条件。

## 验证方案

1. 将当前 14 个 RecoExpandPanel C# 文件编译到工作区 `obj` 验证目录，避免误测旧 DLL。
2. 设置 `RECO_EXPAND_DLL` 后运行 `tools/RecoExpandPanel/tests/Test-TemplateFillNameMatch.ps1`，覆盖名称匹配、单位、局部刷新等既有行为。
3. 增加或扩展反射测试，验证：
   - 同一批名称读取只创建并复用一个上下文；
   - `.xlsx` 定点读取与 NPOI 对代表性文本、数值、公式缓存值和空白单元格返回一致；
   - 定点读取故障时可回退 NPOI；
   - 窗口构造和用户切换模板后的刷新行为正常。
4. 使用当前约 4.6 MB 的 2024 工作簿做只读基准，比较优化前后按名称生成模板相关读取耗时。
5. 检查 Git 差异，确保只包含本设计涉及的源码、测试和文档，不混入用户现有运行配置或业务文件变化。
6. 软件进程关闭前不覆盖运行目录 DLL；代码与测试通过后，再按项目部署规则决定是否构建和部署。

## 完成标准

- 所有既有模板铺量回归测试通过；
- 代表性单元格读取结果与原 NPOI 路径一致；
- `.xls` 行为不变，`.xlsx` 失败回退可用；
- 模板窗口初始化不再重复枚举目标工作簿；
- 大型 `.xlsx` 的批量定点读取不再发生按单元格重复整簿解析；
- 不修改主体业务逻辑和用户数据。
