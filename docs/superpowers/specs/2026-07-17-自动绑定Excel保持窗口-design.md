# 自动绑定 Excel 保持窗口设计

日期：2026-07-17  
范围：`tools/RecoExpandPanel/` 中“自动匹配 Excel 工程量”窗口的“全部绑定”交互

## 1. 背景与问题

当前用户点击“全部绑定”后，窗口会先保存所有已勾选且具备有效 Excel 表达式的定额绑定，然后设置成功对话框结果并立即关闭。用户无法在同一个窗口内继续检查、调整或再次绑定，且窗口左下角状态栏没有显示本次实际保存成功的绑定数量。

## 2. 目标

- 点击“全部绑定”后保存符合条件的勾选项，但保持窗口打开。
- 保存成功后，在窗口左下角现有状态栏显示本次实际保存成功的数量，文案为“已全部绑定 N 条。”。
- 保留“取消”按钮和右上角叉号的关闭能力。
- 保留“单个绑定”、自动匹配、手动匹配、勾选和树筛选等现有行为。

## 3. 非目标

- 不移除或改变底部“取消”按钮。
- 不改变哪些行可参与“全部绑定”的筛选规则。
- 不在成功后清空勾选、重新匹配或刷新整个预览表。
- 不改变 Excel 绑定数据结构、数据库结构或同步逻辑。
- 不扩大插件部署范围。

## 4. 交互与数据流

1. “全部绑定”继续结束表格编辑、刷新表达式，并通过现有 `GetAcceptedItems()` 收集所有已勾选、可绑定且地址和表达式有效的项目。
2. 没有可绑定项目时，继续显示现有提示，窗口保持打开。
3. 有可绑定项目时，保存回调返回实际保存成功的数量。
4. 保存数量大于零时，左下角状态栏显示“已全部绑定 N 条。”，不设置 `DialogResult`，也不调用 `Close()`。
5. 保存失败时，保留现有错误弹窗，并在左下角显示失败状态；不得显示成功数量。
6. 用户可继续修改匹配结果并再次点击“全部绑定”。重复保存沿用现有 `Upsert` 行为，不新增重复记录。

## 5. 实现边界

- `AutoMatchDialog.Accepted` 的保存回调需要把保存结果返回给窗口，使状态栏显示实际成功数量，而不是仅显示提交数量。
- `SaveAutoMatchPreviewAccepted` 在完整保存、运行时重载和面板刷新成功后返回已处理的有效绑定数；捕获异常并显示现有错误弹窗后返回 0。
- “单个绑定”继续调用同一保存回调并保留原有成功提示，不因本次改动自动关闭窗口。
- “全部绑定”移除现有 `DialogResult = DialogResult.OK` 和 `Close()`；“取消”按钮的关闭代码保持不变。

## 6. 错误处理与边界

- `accepted` 为空时不调用保存回调。
- 列表中无效或缺少链接对象的项目不计入成功数量。
- 保存过程任一环节抛出异常时返回 0，保留错误弹窗，并让窗口继续打开以便用户修正或重试。
- 本次不增加新的消息框；成功数量只显示在左下角现有状态栏。

## 7. 验证标准

1. 勾选多条有效匹配后点击“全部绑定”，绑定成功且窗口仍然可见。
2. 左下角显示“已全部绑定 N 条。”，其中 N 等于本次实际保存的有效绑定数。
3. 再次调整匹配并点击“全部绑定”仍可保存，窗口仍不关闭。
4. 没有有效勾选项时保留原提示，窗口不关闭。
5. 保存失败时保留错误提示，不显示虚假的成功数量，窗口不关闭。
6. 点击“取消”或右上角叉号仍可关闭窗口。
7. “单个绑定”行为和提示保持不变。
8. `RecoExpandPanel` 源码编译通过，现有自动绑定入口回归检查继续通过。
