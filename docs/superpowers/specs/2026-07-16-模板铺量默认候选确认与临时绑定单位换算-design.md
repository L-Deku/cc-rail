# 模板铺量默认候选确认与临时绑定单位换算设计

## 背景

名字驱动模板遇到同名多来源时，会把第一个来源的定额或组件组作为当前候选显示，并要求用户通过定额编号下拉确认。当前界面同时锁定了勾选框；当用户接受默认候选时，也必须先操作下拉，容易出现“已显示定额但不能直接勾选”的死区。

模板铺量面板右键“绑定软件选中的定额到此行”会为当前目标工程量临时生成预览行。该路径读取软件定额单位时只检查“单位”和“定额单位”，没有覆盖软件当前可能使用的“计量单位”字段，导致定额单位为空。现有单位换算函数因此无法把目标 Excel 的 `1400 m` 转换为定额 `hm` 所需的 `1400/100`。

## 目标

- 同名多来源仍保留下拉选择，用户可以切换不同来源对应的完整定额或组件组。
- 当前默认候选允许直接勾选；勾选表示接受当前显示的完整候选组。
- 右键临时绑定可靠读取所选定额的真实单位，并复用现有名字驱动单位换算规则。
- `1400 m` 临时绑定到单位为 `hm` 的 `DY-959` 时，预览数量显示为 `1400/100`。
- 不改变名字匹配、组合表达式取数、模板回写、组件组顺序、自动匹配或最终写入流程。

## 非目标

- 不改变同名多来源的候选生成规则和默认候选顺序。
- 不把同名但来源不同的候选合并或删除。
- 不改变组合表达式以第一个操作数名称作为主匹配名、其余操作数按名称取数的现有规则。
- 不新增单位推断规则，也不从工程量名称末尾猜测单位。
- 不修改模板 JSON 或对应框数据格式，不要求重新生成模板。

## 交互设计

### 接受默认候选

同名多来源预览仍以第一个稳定候选作为当前显示值，并保留定额编号下拉入口。

- 当前候选只有一行时，该行勾选框可用。
- 当前候选为多行组件组时，仅组首勾选框用于确认，组员行保持组内联动，避免部分确认。
- 勾选组首即接受当前显示的完整候选组：整组设为已勾选，清除“需确认”状态和浅红提示。
- 用户若不接受默认候选，仍可点击定额编号下拉切换；切换后沿用现有逻辑整组替换并整组勾选。
- 已确认后仍保留候选信息，不影响用户再次通过下拉切换。

### 右键临时绑定数量

右键绑定继续以目标工程量预览组为落位单位，不改变条目定位、定额选择和组件组替换流程。

定额单位按以下顺序获取：

1. 从软件当前定额行读取“单位”“定额单位”“计量单位”字段。
2. 若界面行仍未提供单位，则按已确认的定额序号从当前项目 `定额输入` 中读取该行单位。
3. 取得单位后，调用现有 `BuildNameDrivenQtyText`，以目标 Excel 单位和定额单位计算数量后缀。

例如目标数量为 `1400`、目标单位为 `m`、定额单位为 `hm`，换算结果为 `1400/100`。

若界面行和项目数据都无法取得定额单位，本次修改不新增猜测或阻断策略，保持现有原量行为，避免扩大本需求对其他特殊单位流程的影响。

## 代码边界

修改范围限定为：

- `tools/RecoExpandPanel/TemplateFillPanel.cs`
  - 调整同名多来源当前候选的勾选框可用状态。
  - 勾选时确认当前候选完整组。
  - 右键临时绑定时统一解析真实定额单位。
- `tools/RecoExpandPanel/TemplateFillNameMatch.cs`
  - 仅在需要时增加可测试的“确认当前候选组”小入口；不修改匹配和组合表达式算法。
- `tools/RecoExpandPanel/tests/Test-TemplateFillNameMatch.ps1`
  - 增加默认候选直接确认、界面状态和临时绑定单位换算回归。

不修改 `RecoQuotaData`、模板文件、对应框数据、其他插件 DLL 或业务数据库内容。

## 验证标准

1. 构造两个同名来源候选，初始显示第一个候选；组首勾选框可用，定额编号下拉仍可用。
2. 直接勾选默认候选后，当前完整候选组全部选中，取消浅红确认状态，候选下拉仍可继续切换。
3. 多行组件候选不能只确认其中一条。
4. 软件行仅提供“计量单位=hm”时，右键临时绑定可以读取 `hm`。
5. 目标数量 `1400`、目标单位 `m`、定额单位 `hm` 时，数量结果为 `1400/100`。
6. 既有同名候选切换、重复目标唯一绑定、组合表达式、模板稳定排序、跨工作簿取数和最终写入相关回归全部通过。

## 风险控制

- 候选确认只改变选择状态，不改变候选生成和匹配分数。
- 单位补取使用已选定额序号精确查询，不按编号或名称模糊查找。
- 单位换算继续复用已验证函数，不建立第二套倍率规则。
- 所有修改保持 C# 5 兼容，并限制在模板铺量面板的候选确认与右键临时绑定路径。
