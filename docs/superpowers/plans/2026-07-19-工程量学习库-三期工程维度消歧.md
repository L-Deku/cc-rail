# 工程量学习库三期(工程维度消歧)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 解决"同一工程量在不同工程下对应不同定额/同一定额在不同工程下放不同条目",实现按工程量表精确匹配定额与条目。

**Architecture:** 三层升级:①新聚合表 SignatureEntryMap(签名级条目证据:某工程量+某定额历史上实际放过的条目,按办法分)——这是最强消歧证据;②EngineeringTemplate 归集(条目前缀=工程类型,自动从流水归集,03=桥涵/07=电力/08=房屋);③引擎两遍扫描:第一遍用签名级证据定条目并对整表做"工程前缀投票",第二遍用投票前缀过滤无证据行的条目候选与多 box 歧义。范围不含"一表一模板整表套用"(3B)。

**Tech Stack:** 同一/二期。SQL 聚合表可随时 DROP 重建(全部由 BindingLog 重算)。

**关键事实:**
- BindingLog 936 行,其中 entry_code 非空的行含 method/quantity_name/quantity_unit/target_code——签名级证据的原料齐备。
- 签名 = `NormalizeForSignature(名称)+"|"+NormalizeForSignature(单位)`(截断450),两端算法已一致。
- 工程类型 = entry_code 前 2 位("0821-01-…"→"08")。
- 引擎现状:`TryResolveSmartEntry` 只按定额(EntryByQuota)取 project_count 最高者;`AppendSmartItems(items,row,entry,snapshot,projectEntries,projectQuotaByCode,needConfirm,note)` 不知道签名;快照加载在 `LoadSmartLearningSnapshot`。
- Rebuild-Aggregates.ps1 是聚合唯一入口(两遍扫描定 box,再归并别名/映射)。
